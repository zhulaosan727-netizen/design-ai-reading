从今天起，你可以通过 Figma MCP（模型上下文协议）服务器，在 Codex 中生成 Figma 设计文件。该 MCP 服务器支持双向流转：既能把可运行的 UI 带到 Figma 画布上，也能同样轻松地带回代码中，让你不止于第一个想法，而是在最好的想法上持续深入。

Codex 桌面应用专为智能体化的编码而打造。它提供了一个专注的界面，可以跨项目并行管理多个智能体，在不丢失上下文的情况下跟踪进度，并集成外部工具。这种流畅感并不陌生：在 Figma 中，团队同样可以自如地切换。画布专为探索和迭代而设计，是让最好的想法有空间成形的地方。把 Figma 画布与 Codex 连接起来，这种探索精神就能直接延伸到开发工作流中，为用户开启一种强大的新方式，从原型到生产级应用，一应俱全。

从设计稿开始构建应用

Figma MCP 服务器的核心用途之一，是从 Figma 文件中获取上下文，并将其用于代码生成。Figma MCP 服务器可以从 Figma Design、Make 和 FigJam 文件中获取信息，并在构建过程中传递给 Codex。

开始之前，先打开你打算据以构建应用的 Figma 文件。右键点击选中一个 frame，然后依次选择“Copy as”和“Copy link to selection”。

这些选区 URL 直接链接到 Figma 画布上的某个 frame 或节点。它们可以是单个元素，也可以是一组组件，本质上就是智能体用于生成代码的源数据。选区可以来自 Figma Design、Make 或 FigJam 文件。拿到 URL 后，打开 Codex，选择新建项目或已有项目。接下来，你可以用类似下面的提示词指示 Codex：

help me implement this Figma design in code, use my existing design system components as much as possible.

这样的提示词会指示智能体调用 Figma MCP 服务器中的 get_design_context 工具。该工具负责从 Figma 文件中提取布局、样式和组件信息等关键设计信息，再把这些上下文提供给 Codex 用于代码生成。

除了提取设计信息，Figma MCP 服务器还提供许多其他实用工具；完整列表请查看我们的文档。

从代码到画布

在代码中迭代之后，你会想把设计带回画布，以便比较流程、探索替代方案并验证你的假设。借助 Figma MCP（模型上下文协议）服务器，你无需从浏览器中手动重建，就能轻松把这些界面带回 Figma。使用 generate_figma_design 工具，你可以在几秒内把正在运行的真实界面转换为完全可编辑的 Figma 画框——将真实、可运行的 UI 直接放到画布上，进行更深入的探索与协作。

首先，你需要渲染应用的 UI，可以在本地运行，也可以通过公开可访问的 Web 服务器。然后，让 Codex 帮你生成一个新的 Figma 设计文件。

接下来，Codex 会引导你完成以下步骤：

  1. 决定新建 Figma 文件还是使用现有文件。
  2. 确定文件存放的工作区。
  3. 为 UI 捕获配置应用。
  4. 在浏览器中新开一个应用会话。

应用重新加载后，页面顶部会出现一个新的工具栏，包含以下选项：

整个屏幕：捕获当前显示的整个屏幕的渲染结果，并发送到 Figma 文件。

选择元素：选取页面上的特定组件或元素进行捕获

打开文件：打开 Figma 文件，查看新的设计图层

捕获完所有想要传输到 Figma 的内容后，你可以选择打开文件，或返回 Codex。Codex 已备好 Figma 文件的 URL 等着你。

去而复返：一个 MCP 的故事

现在应用已经构建完成，设计文件也已就绪，你可以开始迭代了。在这里，你可以充分利用 Figma 画布的能力，包括：

  • 添加设计系统组件
  • 将样式、字体和颜色更新为变量
  • 调整布局并添加标注说明
  • 设计各种交互和空状态
  • 协作完成多种变体与探索

完成 UI 的打磨后，你可以按照本文开头介绍的相同步骤，通过 MCP（模型上下文协议）服务器把这些改动同步回你的应用。

当代码与画布相互连通，你就能在执行与探索之间自如切换。这种往返式的工作流释放了 Figma MCP server 与 Codex 搭配使用的真正威力：无论从哪里起步，都能在不牺牲速度的前提下，打造出有意义、高质量的应用体验。
