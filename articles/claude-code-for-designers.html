什么是 Claude Code（面向设计师）？

Claude Code 是一个在代码库中工作的 AI 智能体。你描述想要的效果，Claude Code 就会打开文件、编写代码并运行，全程无需你接触终端。甚至在你还没开始输入之前，它就已经在收集上下文了。

与 Claude Design Skill 的运作方式类似，它会读取团队维护的一份简短文件，其中记录了你们的编码规则和模式，从而理解你的代码库是如何运作的。Claude Code 还会在多次会话之间保留备注，记住过去的修正和偏好。

一旦 Claude Code 连接到你的 Figma 文件，这些上下文会变得更加有用。它可以通过 Figma MCP 服务器读取你的组件和设计令牌（design token），因此生成的代码会与你在 Figma Design 中构建的内容保持一致。

用日常语言描述你想要的效果，最终得到的代码会与你的设计系统保持一致，而不必对着截图去猜颜色和间距。

Claude Code 还可以在你代码库的本地副本上工作。这意味着你可以放心地先试试看效果，不满意再改主意。在你确认可以之前，什么都不会被发布。

这并不意味着 AI 编程工具在包办一切决策。Claude Code 可以写代码，但交互是否合理、是否可以发布，仍需要人来判断。AI 智能体或许会改变工作的完成方式，但把握质量的依然是你。

设计师可以用 Claude Code 做什么

Claude Code 可以融入你设计工作流的这些环节：

  • 设计系统同步。三个冲刺前，你的团队在代码里重命名了一个 Token，却没人更新 Figma 变量。Claude Code 可以读取代码库中的内容并同步回 Figma，让你的文件与线上发布的内容保持一致。
  • 从设计到代码的转换。你做好了一个新功能的设计稿，想在冲刺规划会议前看到它真正运行起来。把画框交给 Claude Code，它就能用你真实的组件构建出可运行的原型。
  • 用真实交互制作原型。你的 Figma 原型模拟了加载态和下拉菜单，但利益相关方可能会问：“数据为空时会怎样？”Claude Code 可以为你构建一个回答这个问题的版本。
  • 文档与审查。你接手了一个毫无文档的组件库，没人记得为什么一半的按钮都不一致。Claude Code 可以撰写文档，并在问题进入 QA 之前标出可访问性问题，包括那些原本可能被忽略的问题。

立即开始

如何将 Figma MCP 服务器连接到 Claude Code

Figma MCP 服务器就像 Figma 文件与 Claude Code 之间的翻译，让 Claude Code 能直接访问你真实的画框和 Token。下面分四步完成设置。

第 1 步：安装 Figma 插件

请确保 Claude Code 已安装，并已在终端中打开。你将在 Claude Code 会话中设置 Claude 与 Figma MCP 服务器的连接。操作如下：

  • 打开 Claude Code，运行以下命令：claude plugin install figma@claude-plugins-official
  • 如果 Claude Code 已在运行，请在安装完成后重启它。

如果运行后没有任何反应，通常是因为你所在的组织禁止了插件安装。请联系你公司账号的 Claude 管理员。

插件装好后，Claude Code 就知道 Figma 的存在了，接下来只需要获得访问你文件的权限。

第 2 步：授权你的 Figma 账号

现在，将 Claude Code 连接到你的 Figma 账号，让它能够访问你的文件。

  • 输入 /plugin 并按 Enter，打开 Claude Code 的插件列表。
  • 在 Installed 标签页中找到 Figma，选中后按 Enter 开始授权流程。
  • 浏览器窗口会自动打开。点击 Allow（允许），连接你的 Figma 账号。
  • 回到 Claude Code，再次输入 /plugin 。此时 Figma 应该显示为已连接。

步骤 3：从 Figma 复制画框链接

Claude Code 连接好之后，你还需要告诉它要处理什么。

  • 在 Figma 中，右键点击你想让 Claude Code 处理的那个画框。
  • 在菜单中选择 Copy link（复制链接）。

这个链接会告诉 Claude Code 该读取哪个画框。

步骤 4：用画框链接向 Claude Code 发送提示词

把画框链接粘贴到 Claude Code 中，说明你的需求，并明确要求复用现有内容。示例：“用 React 构建这个结账表单。复用我们现有的组件，并从我们的设计令牌（design token）中提取间距和颜色值。”

就是这么简单。Claude Code 会读取画框，调用你真实的组件和 Token，然后开始工作。

把 Claude Code 的改动带回 Figma

把改动带回 Figma 的方式和导出时一样：通过 Figma MCP（模型上下文协议）服务器。用提示词让 Claude Code 把文件的当前状态推送回画布，工具就会在 Figma 中直接创建或更新这些内容，生成可编辑的原生图层。

这意味着你不必等待重新构建，就能在 Figma 中看到改动。你可以自己把它拉进 Figma，调整之后再直接交还回去。

如何开始：先尝试这些任务

上手 Claude Code 最好的方式，是从一件小而具体的事情开始。下面是几个切入点：

  • 修正某个偏离规格说明的组件的内边距。
  • 把按钮的间距或颜色对齐到正确的设计令牌（design token）。
  • 修复与设计文件不一致的悬停态。
  • 优化使用了泛泛措辞的空状态或错误提示。

涉及新架构或横跨整个应用的改动，先别碰。这类任务需要的上下文和审查，远超第一次尝试所能提供的，一旦出错也更难纠正。

设计师使用 Claude Code 常见问题

设计师需要会写代码才能使用 Claude Code 吗？

不需要。你可以用日常语言描述想要的效果，其余交给 Claude Code。不过，了解一些基础的 HTML/CSS 术语，比如内边距或组件，能让你的指令更清晰，第一次就更接近你的本意。

Claude Code 会取代开发者吗？

不会。Claude Code 能写出可运行的代码，但开发者仍然提供必要的技术判断，确保代码能在整个产品中正常运作，并经得起生产环境的考验。Claude Code 可以帮设计师独立走得更远，但无法取代工程专业能力。

如果我操作失误，会搞垮生产环境吗？

不会。Claude Code 操作的是代码库的本地副本。如果结果不对或出现问题，你可以撤销或重来，不会影响已发布的内容。

借助 Claude Code 和 Figma 从设计走向代码

设计师用上 Claude Code，就不必再在“描述想法”和“动手实现”之间二选一。把完整画板转化为可运行代码的同时，你的 Figma 文件与代码库始终保持连通。

上手步骤如下：

  • 使用 Figma Design 搭建 Claude Code 工作所依据的框架，让它生成的内容从一开始就与你的 Figma 文件保持一致。
  • 开启 Dev Mode，这样一旦你的改动准备好设计交付，工程师就能拿到准确的规格说明和组件映射。
  • 将 Claude Code 连接到 Figma MCP server，从你的文件中提取组件和 Token。
  • 试试 Figma Make，无需打开终端或接触代码仓库，只靠提示词就能做出可运行的原型。
