01 三句话结论

第一，三维画布真正改的不是「能不能做出深度」，而是你何时才需要把美术方向锁死。过去要先画完平面稿，再交给动效或三维软件；一改颜色、一改数量，就得在工具之间重新交接。Figma Brand Studio 这次把顺序翻了过来：先用很粗的空间构图在运动里试，看这个想法站不站得住，再用看到的结果去发展美术方向（art direction）。有些构图在静帧里很难判断，转起来才知道哪一面该朝向观众。

第二，智能体在这里的职责不是「帮你更有创意」，而是把三维里最磨人的算术拿走。沿 Z 轴按固定间距复制一组字、把几十张卡片排成网格、螺旋（helix）、圆环或随机散布，手摆要么靠目测，要么逐个填数值。设计师 Deanna Gueli 的说法是：来回像探戈，智能体做数学，她做创意。动效设计师 Ben Hill 甚至让智能体写了一个生成式插件，专门管阵列、间距、朝向，以及一键换一种随机布局。

第三，协作能贯穿到动画已经开始之后，是因为形态被做成了组件。场景已经在动，品牌设计师 Yeojin Shin 仍可以通过组件改颜色和渐变，改动会带进动画。剪辑换了镜头位置，调色也可以跟着改，而不用把文件从一个工具再交给另一个工具。对做网站的人来说，还有一句很实际的话：这些三维变换可以直接对应到 CSS，编码智能体也可以经由 Figma MCP 读取或创建三维设计。

02 这不是一篇功能介绍，是一次把决策顺序反过来的实验

2026 年 Config 上，Figma 把一批更「能表达」的材料放进了画布：Figma Motion、由智能体驱动的生成式插件和着色器，以及三维变换。到这篇手记发表时，三维变换进入开放测试，智能体也已正式可用。变换本身是非破坏的：原始图形还在下面，文字和填充会按变换后的层来渲染；再叠上透视（perspective）效果，子元素就进入同一个空间构图。

但 Colby 要写的不是参数列表。Brand Studio 给自己的任务很明确：把这个功能推到 Figma 里所能到达的边缘，并让发布视频本身成为证据。他们从分镜之前就开始探索——品牌元素在静止空间和运动里如何相处，怎样让排版转向观众，怎样让一组图在旋转木马上转，怎样让插画获得体积却仍保持矢量可编辑。

换句话说，视频不是「功能做完之后的包装」，而是一条用来发现用法的工作流。对日常做产品界面的人，这一点比「Figma 现在能转 3D」更有用：当你拥有可以在画布上即时比较的空间和运动，探索本身就可以当成制作。

编者点评：用 AI 做网站的人，很容易把「智能体」理解成「替我出一版首页」。这篇更接近另一种分工：把重复的空间计算交给它，把「转多少度才看得出深度」「这个构图乱还是松」留给自己。会用的人，不一定先会写着色器，但一定先会把任务拆成「算术」和「判断」。

03 先运动，后定稿

Colby 把这次最大的方法变化，写成一句几乎可以当工作原则的话：三维变换让他们把创意决策的顺序反过来了。先在运动里测试一份粗糙的空间构图，看这个想法成不成，再根据看到的东西去发展美术方向。有些想法很难只靠静帧判断；放到运动里，才能在决定最终美术之前，先证明它如何成立。

The agent did math, and I did the creative stuff. — Deanna Gueli / Figma Brand Designer

Deanna 的起点很克制：黑白习作，一个词在空间里重复、错开。她先自己摆好第一处位置，再请智能体按间距沿 Z 轴重复。不必为每一个位置做一次心算，她就可以把注意力放在「层与层之间的空间够不够」「转起来之后会露出什么关系」上。为了把深度再推进一步，她请智能体帮忙搭几何体，把字的动画贴到一根矩形管的表面上，再把这根管子做成组件。

复制组件之后，真正的设计问题才出现：画面里要多少根管子？它们该隔多远？整体旋转时，会不会露出单张静帧看不见的结构？并排放在画布上比较，比在脑海里想象一次三维旋转要可靠得多。运动在这里的作用，不是给已经定稿的平面「加一点动效」，而是让你看见对象其实有多个面，正在空间里转动——而不是一组被斜切过的文字节点。

04 探戈：智能体做算术，人做创意

Ben Hill 遇到的是另一类磨人的劳动。他想靠倾斜、堆叠、旋转，让本来扁平的卡片构图获得深度，但逐张手排既慢又不准：要么靠目测，要么给几十个对象手动输入数值。

Laying out a bunch of elements in 3D space by hand is tedious and imprecise. — Ben Hill / Figma Brand Motion Designer

他的解法不是「请智能体直接给出更好看的构图」，而是请它做一个生成式插件，把重活接走：把选中的对象排成网格、螺旋、圆环或随机散布，并提供朝向、间距，以及一个能换另一种随机布局的滑杆。阵列有了，他才能生成多种变化，在空间里移动它们，并在画布上并排比较。

这是一种很值得学的分工。智能体擅长把「重复 + 可参数化」的动作做稳；人擅长判断哪一种乱法是松弛，哪一种乱法只是散。插件给出的是可控的变化范围，不是一张完成稿。设计师仍然要选，而且要为这个选择负责。

编者点评：如果只记住「让 AI 做三维」，下次你仍会写下「帮我做一组更有空间感的卡片」。更好的吩咐是：先规定媒介（静帧还是循环、在页面上的尺寸），再规定阵列类型和参数范围，最后明确哪一步由你来选。智能体若一开始就连美术一起猜，你得到的往往是一种看起来很 3D、却没有决定的平均深度。

05 用占位形先找空间关系

Ben 在选定随机散布那种更松的布局之前，用的是占位形状（placeholder shapes）。深度、平衡、运动可以先被单独看待，不必同时发明摄影、图标和纹理。这和做界面时「先用灰盒对布局」是同一类纪律，只是对象从栏宽变成了 Z 轴上的体量。

Deanna 的黑白字习作做的是同一件事。颜色会引诱你过早喜欢某一版；去掉颜色，你才能看见重复的词在空间里是挤在一起，还是已经开始形成一个可旋转的结构。等空间关系成立了，再把占位卡片换成摄影、圆、线和别的图形元素，并继续用品牌组件去改。

一个可直接搬到产品站的例子：你要给「本周洞察」做一屏营销英雄区，计划用六到八张洞察卡片形成一个很浅的三维圆环。不要先生成精致的卡片视觉。先用同等大小的灰矩形，让智能体按圆环阵列、给出间距和倾斜的几档变化，在运动里看：转过 30 度时，前面那张会不会挡住后面的标题？圆环半径再大一点，会不会读成散落而不是一个整体？选定空间参数之后，再把真卡片、真数据和品牌色填回去。

06 做成组件，美术方向就可以还开着

把管子、卡片和品牌图形做成组件，看起来像设计系统里的老习惯，在这里却解决了一个三维工作流里最贵的问题：动画开始之后，美术还能不能改。

文中有一个很具体的协作片段。场景已经在动，Yeojin 仍然可以通过组件调整颜色和渐变，这些修改会带进动画。剪辑往前推进时，某组字体镜头被挪到了视频里的另一个位置，团队可以改它的调色，让它跟前后镜头相处，而不用回到某个「已经锁死的三维文件」里重出一版。

Colby 强调，工作因此可以一直是协作的。品牌设计师在动画开始后改颜色，动效设计师继续收运动；剪辑成型时，这些决定是在上下文里做的，不用等谁交出一个可打开的工作文件。画布成了共同的实验场，也让更多人能进入过程。

07 着色器是表面，也是时间

空间站稳之后，Ben 用着色器继续推外观：给资产加上表面处理，扫过一层光，让平面的卡片读出纹理和体积。布局、美术方向和动画是一起演化的，每一轮都给下一轮提供证据，而不是三条互不往来的流水线。

另一段探索把问题问得更狠：一组矢量形状，能不能变成有体积的插画？他先用灰度搭一朵花，仍然是先解决形体和构图，再进入视觉处理。随后用渐变映射着色器（gradient-map shader），把画面里的亮部和暗部分配成不同的颜色。真正巧妙的一步，是给着色器的偏移（offset）做动画——颜色在渐变里移动，看起来就像光在花瓣上扫过。

这里有一个对「独特审美」很有用的提醒。许多 AI 默认界面也爱发光、玻璃和金属，但那往往是一种贴上去的风格词。Brand Studio 的用法是把表面处理绑在已经成立的形体和运动上：先有体积，再有光怎么经过它。没有前一步，着色器只是一层时髦的皮。

编者点评：如果你正在用智能体做官网英雄区，与其提示「加一点玻璃和光泽」，不如分成两步。第一步只允许灰度或单色，先把分层、遮挡和运动做对；第二步再指定一种表面：颗粒、金属、或沿某一方向扫过的光，并写清它要服务的动作（例如随滚动轻轻扫过标题）。表面必须能解释运动，否则它只是在学一种大家都会的「AI 光」。

08 一放到真实页面里，运动就要为动作让路

花本身可以很任性。把它放进一个虚构品牌的首页概念里，和 Gilles Desmadrille 做的字标、图标、动画排版放在一起，运动逻辑就变了。Ben 说，原来的花更像手持摄影机的流动镜头；放到首页里，他们希望它更简单，并且和滚动动作绑在一起。于是运动被减掉一截，时间也被重新对准字的动画。

这是整篇里最接近产品设计的一句教训。三维和着色器很容易自我陶醉：旋转越华丽，越像「我们用上了新材料」。可一旦对象要住在真实页面里，观众的动作（滚、滑、拖）就会变成新的节拍器。为发布视频成立的运动，不一定为落地页成立。先把最放得开的探索做出来，再根据它将要进入的媒介往回减——这个收的动作，本身就是设计。

10 可粘贴：空间构图 brief，以及给智能体的任务

下面这份 brief 不是原文里的模板，而是编者按他们的工作流改写的，可直接贴给 Figma 智能体，或贴给能操作画布 / 写小插件的编码智能体。先把判断写完，再让它动。

媒介：静帧 / 循环 / 只播一次；它在页面上的位置和尺寸：________
目的：让观众在两秒内感觉到深度，而不是认出这是「斜切过的卡片」
空间任务（只选一种先做）：
- 沿 Z 轴重复当前对象，间距 ____，重复 ____ 次；保留我摆的第一个位置
- 把选中对象排成：网格 / 螺旋 / 圆环 / 随机散布
  控制项：间距、朝向、随机种子；每种至少给出 3 个并排可比较的变体
约束：
- 先用占位矩形或单色，不要生成摄影、插画或品牌色
- 不要改我已锁定的原件，复制后再变换
- 把重复的形体做成组件，颜色和内容要可替换
验证：
- 在运动里播放一次完整旋转 / 一次页面滚动
- 指出哪一版在 30 度和 60 度时遮挡最少、层次最清楚
- 等我选定空间参数后，再替换内容和表面处理
表面（第二步才做）：着色器类型 ____；光的方向 ____；它必须服务的动作 ____

若你要的是「写一个小插件」而不是「直接排一版」，把第一句改成：为选中的框架做一个生成式插件，提供网格 / 螺旋 / 圆环 / 随机四种布局，以及间距、朝向和一个切换随机布局的滑杆。不要替我选择最终构图。

11 自查清单

  1. 我是先在运动里验证了粗糙的空间构图，还是先把颜色和摄影锁死了？
  2. 智能体有没有接管沿 Z 轴的间距、阵列和重复？还是我在给几十个对象手填数值？
  3. 第一轮是不是只用了占位形或灰度，好让自己只看深度、平衡和运动？
  4. 重复的形体是不是组件？同事或未来的我，能不能在动画开始之后改颜色，而不拆掉运动？
  5. 我比较过至少三版并排的空间变体，还是只在脑海里想象它旋转起来的样子？
  6. 如果这组三维要住进网站或产品，运动是否已经为滚动、拖拽或滑动减过一刀，而不只是视频镜头？
  7. 表面处理（着色器、扫光、颗粒）是不是绑在已经成立的形体和动作上，而不是一句「再精致一点」？
  8. 需要交给开发时，我是否查看过对应的 CSS transform，或让编码智能体通过 Figma MCP 读取这些三维属性？

13 边界：它通向 CSS，也仍要人决定转哪一面给观众看

工具仍然有边界。三维变换目前是开放测试，面向 Full 席位；它能做的是把画布上的对象放进共享空间，不是把 Figma 变成一套完整的影视级三维流水线。发布视频可以把材料推到边缘，日常产品界面往往只需要浅得多的深度。用得多并不等于用得对。

它也没有取消判断。智能体可以沿 Z 轴排得非常均匀，插件可以一键换一种随机布局，但「这一种乱是松弛，那一种乱是散」「这根管子转过 40 度时才看得出多层关系」，仍然要人在并排的变体前面做决定。探戈成立的前提是：有人负责创意这一步，而不是把整支舞都交给算术。

好在这条探索不是只停在视频里。选中三维图层，可在 Dev Mode 里查看并复制精确的 CSS transform，包含每个轴上的深度和旋转；编码智能体也可以通过 Figma MCP 读取或创建三维设计。对要自己做网站的人，这意味着画布上的一次空间实验，有一条进代码的路，而不必在另一种工具里把透视重新估一遍。

若只记住一件事：不要先把美术方向锁死，再请求「加一点三维」。先用占位形在空间里摆，让智能体做间距和阵列，把草稿转起来看；等你看见哪一面向着观众、光该怎么经过它，再把颜色、摄影和表面处理铺上去。智能体会算术，但通常要等你告诉它，运动是用来做决定的，不是用来装饰已经定稿的平面。
