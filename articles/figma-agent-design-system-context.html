这些上下文大多已经存在于你的设计系统中：从智能体应使用的组件和 Token，到说明它们如何组合的文档化规则和示例。难点在于确保智能体在需要时能够获取这一切。下面介绍如何让它了解全貌。

从事实来源开始

你的设计库包含智能体所需的最基础的构建模块。将已发布的库连接到智能体，就为它打下了这个基础。连接之后，智能体就能识别哪些资产是团队认可的，并在产出中使用这些组件和 Token。

要让 Figma 智能体访问你的库，请打开智能体对话，在提示词输入框中选择“Libraries”，然后选择本项目要使用的已发布库。

假设你的团队正在设计新的结账流程。如果你让智能体构建一张订单摘要卡片，它可以直接调用库中已定义的组件和变量。它可能会使用你现有的 Card/OrderSummary/Default 组件、获批的按钮变体，以及你的间距和颜色变量来完成设计，而不是从零创建一张带有自己样式和结构的新卡片。

当你希望 Figma 智能体修改产品中某个特定位置的特定素材时（比如替换屏幕上的某个按钮），可以用 @- 提及你希望它使用的组件或 Token。

你的库对组件及其行为定义得越清晰，对智能体就越有用。这意味着要使用有意义的组件名称、定义属性和变体、应用变量，并构建可复用的模式，以展示较小的部分如何组合在一起。这些细节能让智能体更清楚地判断每个素材的用途和预期行为。

用指南明确团队的判断标准

指南中应该包含什么？

→ Figma 智能体应始终遵循的规则

→ 这些规则的例外情况

→ 需要避免的错误及正确做法

→ 如何在相似的组件、变体或模式之间做选择

智能体获得你的库之后，就知道有哪些构建模块可用。但有些决策无法从库本身看出来，比如何时使用某些组件，或者这种用法在什么情况下有例外。指南是附加在已发布设计库上的书面说明文件，你可以在其中沉淀这些判断。启用了库的任何提示词都会自动包含它们，让智能体在创建新设计时有据可循，而无需每次都重复说明。

当智能体从零开始创建设计时，指南的效果最好。我们正在努力提升它在编辑现有设计时应用指南的一致性。

要添加指南，请打开你的设计库，然后依次进入 Library → Manage guidelines，上传包含指南的文件，并点击 Apply changes。

例如，假设你的库同时包含主要按钮和次要按钮，但团队在结账页面的“提交订单”行动号召（CTA）上始终使用主要按钮。你可以把这条规则写进指南，让智能体知道在这种情况下该选哪一个。你也可以为“返回”等操作指定使用次要按钮，让智能体有明确的规则可循。这些指南会一直附加在库上，让你的团队在用智能体创建新设计时可以复用这些指导。

向 Figma 智能体展示你的系统在实践中的运用

Figma 智能体所用上下文类型，简而言之：

指南（Guidelines）是团队使用设计库的长期规则。它们始终附属于设计库，并适用于之后的所有新工作。

设计库示例展示团队在实践中如何组合组件和模式。

添加上下文可以为 Figma 智能体提供与当前任务相关的参考，例如特定的 Figma 文件或画框。

Skills 用于沉淀你希望 Figma 智能体遵循的可重复流程。

给智能体看一个成品应该是什么样子，往往比用提示词反复解释更有效。就像你会把现有的结账页面交给同事作为起点一样，你也可以把一份设计交给智能体，让它在此基础上调整。

Examples 和 _example 区分大小写。对于组件集，请将命名或页面位置应用于父级组件集，而不是单个变体。可参考 Material 3 Design Kit。

要将设计添加到提示词中，请点击 + → Attach Figma files，然后选择或粘贴相关设计。

对于希望智能体在今后工作中复用的模式，可以将完整设计作为组件发布到 Examples 页面，或在其名称末尾添加 _example。如果示例只针对你当前的工作，不一定是会重复使用的模式，则将其作为上下文添加到当前提示词中。你也可以直接把画框或图片粘贴到聊天中，或让智能体把截图转换为可编辑的设计。

例如，你可能要在结账流程中添加一个收货地址表单。设计库提供了表单字段和复选框，但仅靠这些组件，并不能说明团队如何组织收货地址表单，比如哪些字段同排显示，或者公寓门牌号等选填字段如何呈现。以往设计中的一个示例可以展示团队如何对字段分组、如何处理间距，让智能体获得一个可针对此次结账体验调整的起点。

将重复的指令转化为 Skills

创建 Skill 时，告诉 Figma 智能体你希望这个 Skill 做什么，并提供它应遵循的步骤或指令。随后你可以预览并编辑该 Skill，包括直接在 markdown 编辑器中修改。

你也可以使用来自 Figma 社区的 Skills，或分享你自己的 Skills 供他人使用。

我们很多人都在一遍遍重复同样的流程，无论是审查界面是否符合可访问性标准，还是频繁检查自己用的是不是最新的组件。现在，你不必每次都重写同样的指令，可以把这套流程变成智能体可复用的一项技能 试试这 10 个技能，也秀出你自己的现在你可以直接在 Figma 中为我们的智能体编写技能，让你的观点真正落地。这里有 10 个我们最喜欢的技能，帮你开个头。。技能是一组你只需教给智能体一次的指令，之后在任何对话中输入正斜杠 (/) 即可触发。你无需每次重写同样的提示词，或重走同样的流程，只要发布一个技能，供团队或整个组织使用。

例如，/design-system-audit 技能可以对照你的库检查选中的界面，并标记脱离的实例、硬编码值、误用的组件以及可访问性缺口。/analyze-components 技能则可以检查你的组件，找出重复项、命名错误，以及与库失去关联的组件。两者都能标记潜在问题并给出后续建议，你可以让智能体去执行，也可以由团队自行处理。

从 Figma 智能体的输出中学习

想让 Figma 智能体修正画布上的错误，可以在提示词中告诉它要改什么，或用 @- 提及你希望它使用的具体组件或 Token。

和使用任何 AI 一样，仔细复核输出依然很重要。审查它的成果时，一旦发现问题，你可以直接在画布上让智能体立即纠正。如果你发现它总是犯同样的错误，这就说明你可能需要回头更新规范、重新审视设计库，或给它提供更好的示例作为参考。
