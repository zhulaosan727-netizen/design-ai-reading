01 先给结论：三句话读懂这篇

第一，Agent 正式 GA，质量与协作面都上去了。人评 eval 对专业设计师约 60%+ 胜率；新能力包括库级 Guidelines（markdown）、跨 Figma 产品找/插上下文、在画布上跟随协作者的 Agent（multiplayer）。

第二，三家不是「换工具」，而是把 Agent 嵌进原有流程：Uber 嵌进设计系统文档与 handoff；Granola 嵌进会议反馈与组件库清理；Atlassian 嵌进动效系统与品牌表达。

第三，Skills 是可分享的工法。斜杠一次教完、社区可发；文档解剖、色 token 映射、状态展开、缓动曲线——都变成可复跑命令，而不是每次重写长 prompt。

02 GA 之后 Agent 能多做什么

Jenny 开篇定调：从 beta 到 GA，输出更跟得住指令、更扛得住长任务。新增三件对团队真正有用的事：

  • Guidelines：库所有者上传 markdown，告诉 Agent「红只用于 Delete，不做装饰」这类选用规矩；启用库时自动带入。
  • 跨产品找上下文：从 FigJam sticky、Figma Slides 文案、Design frame 里找并插入到当前工作。
  • 跟随协作者 Agent：画布上可见队友 Agent 在做什么，multiplayer 不再只是人跟人。
With the agent in Figma, skills run where the work already happens. — Ian Guisard / Uber（大意：Skills 跑在工作已经发生的地方）

与 No.33 的衔接：Guidelines 是「喂饱创建」的第二层；本篇用 Uber / Granola / Atlassian 证明——规矩 + Skills 一旦住在库和画布上，效率跃迁来自「不必切工具」，不是来自更炫的生成。

04 Uber：七平台组件文档，从「多人·数月」到「一人·下午」

Uber 设计系统要服务 七个平台。难点不只是做组件，而是讲清楚：一个组件可带几十种 state / variant / slot / boolean / enum——读错范围，后面全是返工。

Staff PD Ian Guisard 与 Senior PD Niloo Bakhshi 的分工很清晰：Niloo 做高度视觉、细节极重的原型，把新组件愿景做出来；Ian 用 Agent + 自建 Skills 把这些视觉工作翻译成工程可读文档。/create-anatomy 暴露结构，/create-color 把颜色映射到 token 并标硬编码——工程师少挖图层，跨平台来回也少。

关键结果：过去要多人、数月的文档，现在一个设计师一个下午就能发布。Skills 已发到 Figma Community，任何人可对自家组件跑。Ian 自己也受益：误改硬编码色时 Agent 会明确指出。

给 Zhu 的可迁移点：个人站或 B 端小库，不必等「七平台」。先写两个 skill——/anatomy-selected 与 /token-map-colors——对主按钮 / 表单字段各跑一次，handoff 帧比口头讲「看图层」稳得多。

05 Granola：会议批注落画布，把时间留给用户测试

Granola 是 AI 笔记产品，团队小、实验文化重。PD Paavan Buddhdev 的核心诉求：探索时要在画布上摊开十个版本；Agent 帮他快速迭代并吸收反馈，好把精力挪到大局。

打法三件套：

  1. Granola connector：把会议笔记 / 转写直接拉到画布当 annotation——日常 crit 与「Taste the Soup」原型试吃会都适用。以前开会狂记 to-do，现在人能更在场。
  2. Chrome 扩展：从线上 Granola 应用拉真实屏到画布，再让 Agent 清理与 Oats 组件库的连接。
  3. 文案发散：「给我 30 种这个按钮的说法」——把不想干的战术活交给 Agent。
The quicker you can get a design in front of a user, the better. — Paavan Buddhdev / Granola（大意：越快把设计放到用户面前越好）

一切 Agent 用法服务于同一 KPI：更快把设计送到用户面前。

06 Atlassian：动效从专家交接变成系统能力

动效是 Atlassian 品牌与体验的核心，但常常「设计了却上不了船」。小动效团队把动画插画做成可复用组件；Agent 成为这套系统的延伸。Senior PD Alexandra Pereira 的表述很准：把专家 handoff 变成 system capability（系统能力），同时保住动效 craft。

日常路径：做 onboarding modal 的设计师从库里选 animated illustration 填 slot；需要定制时，Agent 在 ADS 变量护栏内迭代 easing / duration。企业系统要的是一致性、可访问性、可实现性——与速度同等重要。

案例：PD Davy Fung 用 Agent 做 Slack 沟通 banner / 内部落地页 header 动效——先说要什么，再问「哪里好、哪里不好」。Lead Motion Maxwell Hathaway 认为：更多人在已熟悉的画布上练，taste 会一起被抬高。

动效护栏 = 变量 + 可复用组件 + Agent 迭代。个人站若只有轻动效：先冻 2–3 条 duration / easing token，再写 /motion-within-tokens skill，禁止 Agent 发明「看起来酷但库外」的曲线。

08 个人站 / B 端产品怎么嵌

不要「另开一套 Agent 流程」。对照三家，选一条你已经在做的事嵌进去：

  1. 你常写组件说明 → 学 Uber：选中主组件，跑 anatomy + token 映射，输出一帧 handoff。
  2. 你常开设计评审 → 学 Granola：会议结束后把录音 / 笔记摘要贴给 Agent，要求按画板分区 annotation；或用 /do-try-consider 整理评论。
  3. 你有微动效但没专人 → 学 Atlassian：先建 1 个可复用动效组件 + 变量护栏，再让 Agent 只在护栏内改。
# 最小嵌法（本周可做）
[ ] 启用主 library + 上传 1 页 Guidelines（选用 / 例外）
[ ] Community 安装 /create-anatomy、/create-color（或自写精简版）
[ ] 对「主按钮 + 表单字段」各跑一遍，生成 handoff 帧
[ ] 下一次设计评审：评论用 /do-try-consider 归类
[ ] 若有动效：冻 duration/easing token，禁止库外曲线

09 可复制的 Skill 模板

# /handoff-anatomy-tokens（建议冻成 skill）
目标：为当前选中组件生成开发可读文档帧。
步骤：
1. 画 anatomy：标出 subcomponents / slots / 关键 variants
2. 列出所有颜色 / 阴影 / 描边，映射到设计 token；硬编码标红
3. 输出简短 API：props 名、默认值、禁用态注意点
4. 不要发明库外组件；缺变体时列「需 DS 补齐」清单
输出：同一页新建「Handoff / <ComponentName>」帧

10 自查清单

  • Agent 是否跑在「工作已经发生」的文件里，而不是另开沙盒再复制？
  • 重复文档 / 审计有没有冻成 / skill，并考虑发 Community 或队内共享？
  • Guidelines 是否写了例外（何时用红、何时不用），而不只是原则口号？
  • 会议反馈是落在画布 annotation，还是仍散落在聊天软件？
  • 动效迭代是否绑在 DS 变量上，而不是每次自由发挥 easing？
  • 席位是否匹配（Full seat 等）？协作者是否只在草稿可用 Agent？

收束给 Zhu：三家共同点不是「更会写 prompt」，而是 Agent 住在原流程里——文档、反馈、动效各自嵌一刀。个人站同样：先选一个每周都在痛的环节（handoff 帧 / 评审整理 / 轻动效），冻成 skill + guidelines，再谈「创意表达」。craft、speed、expression 是同一条链上的三个出口。
