• /make-a-type-scale：基于选中的文本构建字号阶梯，并生成对应的字体变量

从今天起，你可以在 Figma 中与智能体协作编写 skill。步骤如下：

  • 让智能体以某个设计画框为参考创建 skill，或按照你提供的具体步骤或指南来创建。
  • 智能体生成草稿后，先预览该 skill，再在对话中投入使用。
  • 测试时持续迭代：编辑步骤、调整格式、请它给出建议，或直接打开 markdown 编辑器手动修改。

1. 为图片添加 X 光效果

创作者：Adele Ix，自由职业者

Skill：/xray-scan

功能：将照片或文字描述转换为逼真的 X 光片，呈现物体的内部细节。它会立即生成两种效果：黑底发光白色，以及白底柔和深色调。

Adele 的自述：“我喜欢做拼贴，这一点在这个 skill 里体现得很明显。我最喜欢的部分是把多张 X 光片层层叠加。它们是单色的，边缘发光，叠在一起就成了非常酷的拼贴，而且每一张单独看很出彩，混合在一起同样美妙。”

2. 找出缺失动效的地方

创作者：Emil Kowalski，Linear

Skill：/find-animation-opportunities

功能：扫描设计稿，找出该有动画却没有的地方，反之亦然。这个 skill 能回答“这里可以加什么动画？”或“怎样让它更有生命力？”等问题。它会提出该添加什么动效、加在哪里，并给出精确数值。你可以自己在 Figma Motion 中实现这些改动，也可以让智能体代为应用。

Emil 的自述：“把这个 skill 指向某一个画框并补充额外上下文（例如页面的目标用户画像）时，效果最好。你也可以用它来避免过度动画，比如问它：‘有没有哪些地方完全不该加动画？’”

3. 为静态构图加入动效

作者：Mallory Dean，Figma

Skill：/camera-pan-and-zoom

功能：围绕所选内容搭建一套 camera rig（一种模拟真实摄像机运动的嵌套图层结构），然后像动效导演设计镜头取景一样，为平移、缩放或翻滚添加动画。例如，它可以先在一组卡片之间做网格巡游，再缩放回完整视图。

Mallory 的原话：“这是一个非常小众的 Skill，但它能在不改动设计中任何画框的情况下，实现镜头的缩放和平移效果。”

4. 找出界面中缺失的细节

作者：Jakub Krehel，Interfere

Skill：/better-interface

功能：为智能体提供 Jakub 自己总结的界面工艺规则手册，涵盖排版、布局、可访问性、动效和产品文案等方面的具体标准。

Jakub 的原话：“从用好一款产品到用上一款卓越的产品，你能明显感受到其中的差别。这通常不是某一件事造成的，而是许多小细节累积的结果。这个 Skill 收录了这些常被忽视、或者并不显而易见的细节和最佳实践。”

5. 自动生成组件文档

作者：Mauro Berteri，Itti Digital

Skill：/component-handoff

功能：将单个组件或组件集转换为画布上可直接分享的文档画框。选中一个组件后，它会生成：

  • 包含名称、版本、负责人和描述的页眉
  • 实时预览
  • 变体网格
  • 注意事项（Do’s and Don’ts）部分
  • 交互与状态拆解
  • 组件的完整结构（anatomy）

Mauro 的原话：“我的理念很简单——把过去要花我几个小时的重复性工作自动化，这样我就能专注于真正的创意工作。借助这个 skill，我把多年经验中验证最有效的设计交付结构打包起来，让任何设计师都能一键适配到自己的设计系统。它具备可扩展、可预测的特点，并且可以直接在 Figma 画布上 100% 编辑。”

6. 将颜色匹配到 Token

作者：Ian Guisard，Uber

Skill：/create-color

功能：将选中的 Figma 组件转化为完整的颜色规格说明。它会把每一处可见的填充、描边和阴影映射到对应的设计令牌（design token）或样式，标记硬编码的颜色，并在各个变体和状态中记录结果。

Ian 的原话：“我最喜欢的示例之一是一个包含多种类型、状态和颜色模式的按钮。当组件使用多层填充或渐变时，它会按叠放顺序列出每一层填充，以及每个渐变节点的位置、颜色和绑定的变量。工程师可以直接根据标注还原这种处理效果，无需逐层手动检查。”

7. 一次性审查你的组件

作者：Amy Ha，Walmart

Skill：/analyze-components

功能：遍历一个页面并清理发现的问题，然后为每个组件建立带实时预览的目录，并且：

  • 标记孤立组件、重复项和命名错误
  • 自动修复问题：克隆孤立组件，并将所有实例替换为修复后的版本
  • 将完整结果写入画布上带样式的审计文档

Amy 的原话：“这真的能省下不少时间。以前我得右键进入主文件，手动把组件复制过来，或者处理幽灵 Token，再手动重新设置所有样式。现在这类批量编辑可以一次完成。”

8. 为每种状态而设计

创建者：Linda Ojo，Paystack

Skill：/ui-state-expander

功能介绍：将任意屏幕、组件或流程展开为完整的状态集合。这个 Skill 能确保每种状态在交付工程团队发布之前都已设计到位，涵盖：

  • 加载态
  • 空状态
  • 错误态
  • 禁用状态
  • 部分数据状态
  • 边缘情况

它会给出触发条件、文案、过渡和实现备注，让一份精美的理想路径视觉稿变成工程师可以直接开发的内容。

Linda 的原话：“每次设计交付，我都会看到同样的评审意见：‘失败了会怎样？’‘空状态长什么样？’后来我意识到，我脑子里的那份检查清单，应该做成一个任何人（无论是人还是智能体）都能运行的 Skill。”

9. 为你的设计做一次评审（crit）

创建者：Joey Primiani，Superfuture

Skill：/superfuture-design-review

功能：依据 UX 启发式原则、可访问性标准、视觉层级、交互设计和产品思维对文件进行评审，然后将每条备注按红绿灯体系分类：

  • 红色：阻碍项
  • 黄色：建议修复项
  • 绿色：已经做得好的部分

Joey 的原话：“这个 Skill 体现了我个人的评审流程：在平衡可用性、可访问性、产品策略、视觉设计和商业目标的同时，按对用户的影响来排定反馈的优先级。”

10. 为可用性测试创建讨论指南

创建者：Neha Kodi，Figma

Skill：/usability-test-guide

功能：基于 Neha 作为研究员的最佳实践，为可用性测试提供一份可直接使用的讨论指南。这个 Skill 会审视准备用于可用性测试的设计流程，然后在画布上每个画框旁直接添加贴合上下文的引导提问。

Neha 的原话：“测试与学习是我在 Figma 工作的核心，这个 Skill 运用了几条我绝不妥协的做法：让任务围绕参与者的目标展开，保持追问的开放性，并根据设计流程的繁简来调整问题数量。”
