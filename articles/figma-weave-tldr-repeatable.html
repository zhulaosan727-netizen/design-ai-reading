01 先给结论：三句话读懂这篇

第一，Weave 卖的不是「又一个文生图框」，而是把生产过程做成可编辑的图。节点（Node）连成工作流（Workflow）；同一起点可以分出分支（Branch）试方向；跑通的流程还能打成 Weave tool，让队友不必碰底层节点。

第二，控制力来自「节点级编辑」，不是「再赌一次生成」。校色、合成、Levels、Trim、Crop、Painter 都以节点形式挂在链路上；细节该手改时就手改，省掉 credits，也避免整条链路被一次含糊提示带偏。

第三，与 Figma Design 保持连接，是品牌一致性的便宜保险。用 Figma node 把画板贴进 Weave，改原 frame 会反映到节点——让已定的版式与品牌决策继续指导创意生产，而不是在另一边重画一遍。

概念一句话对 Zhu 的用处
Node画布上的一步积木（素材 / 提示 / 生成 / 编辑）把「哪一步坏了」说清楚
Workflow连起来的节点序列，从起点到成品过程可见，可回退到更早节点
Branch从同一起点分出的探索路径森林 vs 山顶并排比，不必覆盖原版
Weave tool打包后的工作流，使用者只交输入个人站多尺寸物料可模板化

02 四个词先对齐：Node / Workflow / Branch / Weave tool

原文开篇就把术语钉死。Node 是单个积木；Workflow 是连成成品的路径；Branch 是另辟一条方向却保留原起点；Weave tool 是「给不会摸节点的人用的封装」。读本建议把最后一项当成产品化门槛：只有当你愿意让队友在无人讲解的情况下跑通，它才算真正可复用——否则还只是你自己的私人节点画布。

和 Skill / MCP 的对照：Skill 写的是「怎么判断与执行」；Weave tool 写的是「这条创意生产流水线怎么跑」。一个偏流程知识，一个偏媒体产出链路——别混成同一种「可复用」。

03 探索：分支与同提示多模型对照

探索期 Weave 给的是并排带宽：同一张背包产品图，可以接到两个图像编辑节点——一个提示放进森林，一个放上山顶；再各自校色或转成短视频。两条 Branch 都留在画布上，提交方向之前仍能回看。

同提示也可过不同 AI 模型并排比结果，选更贴 look 的那条继续。关键纪律：每个版本都连回产生它的步骤，比较的是「路径」，不是散落在桌面的孤立 JPG。

04 控细节：编辑节点，而不是再写一轮提示

文中点名的编辑节点包括：

  • Color correction：整体色相与观感（含饱和）
  • Compositor：图层叠图 / 视频 / 文字 / 形状
  • Levels：阴影、中间调、高光
  • Trim / Crop：剪短视频；按预设或自定义比例裁切
  • Painter：笔刷、形状、橡皮直接画

原则很务实：已经喜欢的图，小改动优先手改节点，而不是再花一次生成去「碰运气」。这和读本里反复强调的「AI 加速脚手架、细节判断留给人」一致。

05 复用：把成功路径交给队友

成功工作流保存的是一路上的选择，而不只是终帧。例子：去背 → 贴品牌背景 → 裁成社媒尺寸；下一场发布会只换产品照，处理保持一致。再进一步，把该流程打成 Weave tool：下一任用户上传照片、点 Generate，自动跑完全程。

社区已可发布 Weave tool（文中提到 moodboard→房间 3D、改尺寸等）。对个人站：同一套封面系统、多渠道裁切，很适合先在自己工作流里跑通，再决定要不要封装。

A successful workflow preserves the choices someone made along the way to a finished result. — Emma Webster / Figma Blog

06 和「单次生成」差在哪：一张对照表

很多人第一次打开 Weave，仍会把它当成「更好看的文生图面板」。差别在过程是否可版本化：

单次生成工具Weave 工作流
失败时整段重写提示、重抽奖回到出错的 Node，只修那一步
探索另开对话 / 另存文件，易丢谱系Branch 并排，谱系留在画布
交付队友交终帧 + 口头说明交 Workflow / Weave tool，输入可替换
与设计稿常靠截图搬运Figma node 保持链接
小改动成本常再烧一次 generation编辑节点手改

若你的瓶颈是「还不会写一句好提示」，先练具体提示与参考角色；若瓶颈是「每次战役都从零搭流水线」，才值得把成功路径节点化并打包。

社区 Weave tool 的价值不在「魔法效果」，而在降低搭建税：moodboard→房间渲染、改尺寸适配等，让你先跑通别人的图，再决定要不要 fork 成自己的品牌版本。

07 六条上手纪律

  1. 提示要具体：写清改什么、保留什么。少写 “Make the lighting better”，多写 “Use soft, warm light, keeping the backpack’s color and shape unchanged.”
  2. 给参考图角色：多张参考时用 Prompt node 写明「第一张取色，第二张取插画风格」。
  3. 该手改就手改：提亮、校色、加字——编辑节点优先于再生成。
  4. 逐步搭建、逐步测：早期结果歪了，后面每一步都会叠错；进 Compositor / 生视频前先验收静帧。
  5. 发布前找人盲测：队友不听讲解能否知道该交什么、输出是否有用。
  6. 接住 Figma Design：用 Figma node 粘贴 frame，保持与原稿链接；并排试模型，用结果选模型而不是用品牌偏好赌。

辅助节点：Prompt Enhancer 帮你把提示写细；Run Any LLM 可选模型审/改指令；prompt variables 只改提示里的一段，不必整段重写。

08 什么时候该伸手去拿 Weave

场景痛点Weave 扮演的角色
产品系列上新变体多，无法每件重拍同一处理链换素材
多渠道 / 多市场战役尺寸与市场差异大，又要统一气质分支适配 + 共用上游节点
视频从静帧长出来参考图有了，镜头还没有从参考生成镜头 / refining clips

不该神话的边界：若你还在定视觉 thesis（视觉主张），先把方向想清再进节点图——否则分支只会高效地复制混乱。

09 和 No.28 / No.26 / No.48 怎么排

  1. No.26 判断留给你：Agent 做杂活，人留审美判断——Weave 的「手改节点 vs 再提示」是同一纪律的创意生产版。
  2. No.28 Figma Make 反向交接：设计师改代码推 PR；Weave 则把「设计→创意物料」那一侧流水线化。一个偏工程交接，一个偏生产复用。
  3. No.48 Martin 闭环：少开 Figma、多关 research→code 环；若你的瓶颈是战役物料而不是产品原型，Weave 更贴。
  4. 本篇：把生成与编辑变成可版本、可分支、可打包的图。

10 可粘贴：Weave 工作流检查表

# Figma Weave 工作流检查表（开跑前）
[ ] 起点素材角色写清（产品图 / 版式 frame / 参考 mood）
[ ] 提示写「改什么 + 保什么」；多参考则 Prompt node 分配角色
[ ] 探索用 Branch，不覆盖原路径；同提示至少比 2 个模型
[ ] 细节优先 Color / Levels / Crop / Painter，再考虑重新生成
[ ] 逐步验收：静帧 OK → 再进 Compositor / 视频节点
[ ] 需要品牌一致性：用 Figma node 粘贴并保持链接
[ ] 准备打成 Weave tool 前：换 2 套陌生素材盲测 + 同事无讲解试跑
[ ] 文档一句：这条工具解决什么、输入是什么、禁止改哪些上游节点

11 自查清单

  • 我是在搭「可回退的路径」，还是在堆互不相关的生成结果？
  • 失败时能不能指到具体 Node，而不是整段重来？
  • Branch 是在探索方向，还是在逃避做选择？
  • 小改动是否浪费了一次生成 credits？
  • Figma Design 里的品牌决策有没有断连？
  • 若打包成 Weave tool，陌生人第一眼知道该上传什么吗？
  • 这条流程下周换一批产品图，还能否保持同一 treatment？

一句话收束：Weave 把「灵感偶然成功」升级成「团队可复用的生产图」。节点让过程可见，分支让探索不毁原版，编辑节点把控制权从提示词赌局里抽回来，Weave tool 则把成功选择交给下一个不会搭节点的人。创意生产要的不是更多孤立好图，而是一条下次还能跑的路。
