01 先给结论：Agent 不是没品味

原文开篇很硬：Agent 缺品味，不是因为它笨，而是因为你没给它任何可品味的事实。语言模型会把你留下的每个缺口填成训练数据的统计中心——「好看的现代 Web UI」的中心，就是 Inter、紫色渐变、居中 hero、三张一样的功能卡。你说「clean and modern」，等于在请求平均值，于是你得到平均值。

对 Agent 而言，taste = context：具体参考、真实数值、具名模式、以及把最高概率答案从糊状平均推开的紧约束。下面九种按杠杆从大到小排列。

短引（uiscanner）：「Taste, for an agent, is context.」这与读本多篇 DESIGN.md / Skills / AGENTS.md 同构——品味不是说服模型「有感觉」，而是供应事实。

02 方式 1：真参考，别用形容词

最大单点升级：用具体参考替换抽象描述词。NN/g 关于 AI 原型的研究也指向同一结论：模糊 prompt 失败；修复是指向既有风格或具体产物，而不是描述感觉。「Make it premium」只在同一片平均云里挪几寸；「Build it like Linear's marketing site」一次关掉上千个开放决策。

形容词派参考派
说法premium / clean / modern / delightful像 Linear 营销站 / Stripe 定价页 / 本仓某页
Agent 补全训练中心（Inter + 紫渐变 + 三卡）该参考的布局原型与气质锚点
决策关闭数极少极多（版式、密度、语气一并锚定）

做法：选你真心佩服、且与当前原型同类的 1–2 个站，直接点名。后面所有步骤都建在这个锚上。

03 方式 2：参考落成 design tokens

点名有帮助，但 Agent 仍要猜真实数值。把缺口关掉：抽出 tokens——精确颜色、字体族、type scale、圆角、间距节奏、阴影、动效。Tokens 是外观的原子单位。交给 Agent #635bff 和 14/16/20/24 字号阶，它就不必从训练汤里再发明一套色与阶。

uiscanner 的位置在这里：贴公开 URL → 设计拆解（teardown）：tokens、按区块的结构、以及面向 Claude 的 build prompt。它用视觉 + DOM 读渲染页，能抓到真正的主按钮（而不是源码里第一个 button）、hero 是居中还是分栏、哪些图是装饰（并给出原创重做提示）。它描述与 tokenize，不复制或再托管原站资源字节——你在自己的栈里按 tokens 与结构重建。

ui_teardown("stripe.com", target: "landing")

04 方式 3：给组件，不只给 token

Tokens 定调色板；components 定形状。同一个 #111 按钮在 8px 网格上仍可有十种做法。若项目有组件库（shadcn/ui、Radix、自研 primitives），按名字点名：「用我们的 Button 和 Card，不要新造。」指向真实组件越多，跨会话一致性越高。

失败模式：Agent 默默在三个文件之外再实现一个已存在的按钮。显式引用组件名即可切断。

只给 tokentoken + 组件名
色与间距对，结构仍漂移形状与 API 收敛到现有 primitives
易出现「几乎一样」的私货 Button复用率上升，设计系统不被掏空

05 方式 4：上下文里放真例子

品味最适合示范传递。别只描述约定——把仓库里 2–3 个真正做好的组件丢进上下文，说「match this」。Agent 从好例子推断间距习惯、命名、prop 模式与克制，远优于一段规则散文。

这是清单上最便宜的高杠杆动作：例子你已经有了，放在模型眼前，而不是假设它知道。

Zhu 实践：与其写「卡片要有品味」，不如 @ 一篇读本卡片组件 + 一篇告警组件，并附加硬禁令：这两类表面禁止左侧竖向色条 / border-left accent bar。

06 方式 5：MCP 接通活的设计上下文

Prompt 是一次性的；Model Context Protocol（MCP）服务器是 Agent 可按需拉取的结构化事实管道。Figma 团队把 MCP 说成 unlock，正因它用准确、机器可读的上下文替换猜测：工具要 token 或组件，服务器返回真值，而不是幻觉。

uiscanner 可作为其一。接入 Claude Code 一例：

claude mcp add uiscanner -- npx -y uiscanner-mcp@latest

亦可作为 Claude Code / Cursor / Codex 的 MCP 客户端工具。暴露五个工具：

工具作用
ui_teardown(url, target?)扫描页面 → tokens、结构、build prompt
ui_probe(url)廉价预检，不消耗 scan
get_teardown(id|link)取回已完成 teardown
retarget_teardown(id, target)不重扫，把 build prompt 改到另一 archetype
whoami()报告套餐与剩余 scans

Target archetypes：landing / dashboard / marketing / ecommerce / portfolio / mobile / general。stdio-only，跑在本机。每次扫描返回 id 与可分享的 uiscanner.com/t/<id> 链接。

07 方式 6：Adopt / Avoid 风格简报

方向清楚后，写成短而有立场的 brief，让 Agent 每次都读。最强模式是显式 adopt / avoid：模型被拉向最「像那么回事」的答案，所以列出避免项与列出采用项同等重要——例如：不要三张一模一样的卡片横排、不要假精确统计如 99.99%、不要处处渐变、不要滥用 em dash。十条锋利规则胜过千字散文。

放进仓库（AGENTS.md / DESIGN.md / 系统提示），避免每次重贴。

## Adopt
- 中性浅灰页面底（无绿偏 / 蓝偏灰）
- 状态用标签、图标、表面色温、顶边或全框
- 中文术语括注英文（design tokens）

## Avoid（硬）
- 卡片 / 告警 / 详情面板 / 列表行左侧竖向色条或 border-left accent bar
- Inter + 紫渐变 + 居中 hero + 三功能卡的默认套餐（无参考时）
- 形容词式口味（premium / clean）代替具名参考

08 方式 7：把约束写进 prompt

即便以上都有，请求本身仍需要边界。GenDesigns 的 AI UI prompt 框架可当清单：platform、user、output spec、mood/style、patterns/components、technical constraints。事先声明框架与样式系统（Next.js、Tailwind、我们的 tokens），点名布局模式（「split hero、bottom tab、bento grid」），迭代时用精确值。「加 32px 垂直内边距」优于「再松一点」——模糊说法会再次邀请平均值。

09 方式 8：视觉反馈环

初稿就是初稿。真正拉开差距的是生成之后。Agentic Coding Handbook 的 visual feedback loop：渲染 → 截图 → 把截图喂回 Agent → 指出问题 → 再生成 → 重复。截图配 prompt，让模型看见真实输出而非想象输出；能标注就标注问题区域，优于纯文字描述。

有参考时：把你的截图与起始 teardown 对照，缺口一目了然。

循环
渲染 UI → screenshot → 标注问题区 → 再生成
         ↑__________________________|
对照：teardown / 参考站 / 上一版屏幕

10 方式 9：用 eval，别用 vibe

在看输出之前先定义「好」——按标准打分，而不是按心情。轻量 UI eval 可以是每次都跑的短清单：是否使用我们的 tokens、是否复用现有组件、是否达到 AA 对比度、是否避开禁模式、间距与层级是否贴合参考。让 Agent 对照清单自检；多屏构建时与前一屏做 diff，抓漂移。Vibe-check 只能撑一屏；eval 能撑五十屏。

VibeEval
「感觉差点意思」可勾选的规则与回归用例
不可复现可跨会话 / 跨人复跑
一屏够用多屏防漂移

11 贯穿线与 Zhu 对照表

每一条都是同一动作在不同高度：用具体事实替换开放决策。参考胜过形容词，tokens 胜过参考名，组件胜过 tokens，例子胜过描述，活的 MCP 胜过一次性粘贴，风格简报胜过记忆，约束胜过希望，反馈环胜过初稿，eval 胜过 vibe。品味不是说服模型拥有的东西——是你供应的上下文；供应越多，平均值赢的空间越小。

12 可粘贴清单与 prompt 模板

# 九步供应品味（每次新界面前扫一遍）
[ ] 1 点名 1–2 个真参考（非 premium/clean）
[ ] 2 抽出或拉取 tokens（色/字/半径/间距/影/动）
[ ] 3 点名现有 Button/Card/… 禁止私货重造
[ ] 4 上下文放入 2–3 个本仓好例子
[ ] 5 需要活上下文时接通 MCP（teardown / 设计系统）
[ ] 6 AGENTS.md / DESIGN.md 写 adopt + avoid
[ ] 7 Prompt 含：平台、用户、输出规格、模式、技术约束、精确值
[ ] 8 截图反馈环：标注 → 再生成（对照参考）
[ ] 9 跑 UI eval 清单，而非 vibe
[ ] 硬禁：卡片/告警/详情/列表行 — 无左侧竖向色条 / border-left

# Prompt 模板（可直接改）
Build a [archetype: landing|dashboard|…] in [Next.js + Tailwind].
Reference: [Linear marketing / Stripe pricing / 本仓 path].
Use tokens from [./design/tokens.md] and components [Button, Card, Alert].
Match the spacing/naming of these examples: [@FileA, @FileB].
Constraints:
- No left vertical accent bar / border-left on cards, alerts, panels, list rows
- Status via tags, icons, surface tint, or top/full border
- Exact values when iterating (e.g. py-8 = 32px), no "more space"
Self-check against eval: tokens · reuse components · AA contrast · avoid list · hierarchy vs reference.
