Skills 与设计系统相辅相成。设计系统为智能体提供合适的组件、模式和 UI 元素来进行构建；Skills 则补上团队其余的专业经验，比如运用你的品牌语气和合规准则、评审作品、遵循评审流程，甚至在更大的工作流中调用你的设计系统。

Skills 能帮你从更敏锐的角度审视作品。它们可以挑战一个想法、帮你提出更好的问题，或从特定视角评审设计。它们还能帮助团队落实并维护共同标准，从 UX 文案准则、可访问性检查到产品原则。下面是我们创建的几个用来提升工作质量的 skills：

  • 模拟利益相关方的反馈风格：把某人给你反馈的示例（公开评论、过往评审意见、文件中的备注）交给智能体，再通过提示词让它把这个 skill 应用到你的作品上。我们基于 CEO Dylan 的评论做了一个，设计师可以在进入评审前先对作品做一次压力测试。
  • 维护 UX 文案标准：把风格指南交给智能体，让它先过一遍，找出不一致之处。Figma 的 UX 文案团队做了一个遵循我们大小写、标点等规范的 skill，让文案作者能把精力放在更实质的工作上。
  • 获得新用户的视角：运行一个 skill，以首次使用者的身份评审体验，帮助发现摩擦点和缺失的上下文，而这些问题往往是深度了解产品的人（比如产品设计师）看不到的。

一次构建，随处可用

有些 skills 能让团队的例行事务更容易运转。它们可以帮助新成员入职、准备项目空间，或为新项目提供一致的起点。规律很简单：如果团队每次都以同样的方式做某件事，它大概就值得做成一个 skill。以下几个值得一试：

  • 进度速览：汇总文件或项目的近期动态，让离开一段时间后重新加入的人无需翻遍评论串，也能快速跟上进度。
  • 评审准备清单：智能体会就你的项目向你提问，收集用户画像、工作范围和评审对象等上下文，然后创建一个评审页面，并附上引导式讨论提示词。我们在构建这个 skill 时参考了 Nielsen Norman Group 在研究问题方面的最佳实践，确保讨论问题能引发更深入的对话。
  • 评审回顾：将评审中的反馈整理成按主题分组的后续计划，包括已做出的决定、待办事项和暂缓事项。我们的 skill 版本会生成一张回顾卡片，可以放在画布上，也可以粘贴到 Slack 讨论串中，这样会后不会遗漏任何内容，信息也能流向该去的地方。
