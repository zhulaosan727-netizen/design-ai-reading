我经常在 X 上发布这类 AI 设计演示。每次发完，总会有人问：“为什么模型能给你做出这么多惊艳的东西，我一试就只能得到千篇一律的垃圾？感觉你用的完全是另一个模型。”

我用的并不是另一个模型，只是我从手头的模型里榨取到了更多价值。大多数人只看到了 AI 1% 的创造潜力。我想告诉你如何挖掘剩下的 99%。

AI 模型本可以展现惊人的创造力，但训练方式压抑了这种创造力。大语言模型是下一个 Token 的预测器：每一步，它们都会查看一段文本序列，并根据数百万个示例预测接下来会出现什么。结果可能会由人类打分，再把评分反馈给模型。这会让模型学会做出稳定、保险、迎合所有人偏好的选择。

这让常规的大语言模型（LLM）擅长处理大多数任务，却成不了好设计师。要完成一个设计，LLM 必须逐个 Token 地把它构建出来。每当需要做设计决策——用什么颜色，或如何排布元素——模型都会填入它认为最能让所有人满意的 Token。结果，设计往往千篇一律、平淡无味，堪称“委员会式设计”的极致案例。

而出色的设计恰恰始于感受，目标是引发情感共鸣。它会打破常规，用令人难忘、出人意料的选择取悦用户。出色的设计与 LLM 的天性截然相反——后者在每一步都会选择最可预测的那个答案。

不过，如果我们能让模型跳出最可预测的选择，就能触及大多数人错过的、广阔的创意版图。

这是我在管理 AI 设计师之前，从管理人类设计师身上学到的一课。在 Apple 的大部分职业生涯里，我带领一支研发团队，设计探索性的未来 AI 产品。早期，我们对用户界面“应该如何运作”的先入之见限制了创造力，让我们一再回到老套的想法。通过严谨的方法和新的流程，我们学会了不再重复那些舒适区里的东西，而是去探索可能性的边缘，创造出新的东西。我们也成了专家，能把细节打磨到 Apple 级别的品质。

离开 Apple 之后，我一直在把同样的流程应用到我与 AI 的协作中。过去几年里，AI 智能体已经变得极其强大。它们几小时就能完成过去我的团队需要数周才能做完的工作。只要引导得当，它们能做出与众不同、前所未见的设计。

我从 双钻设计流程中获得了一些灵感，并为一支由 AI 智能体而非人类设计师组成的团队重新设计了设计流程：

  1. 发现（Discover）：探索多种方向，撰写大胆而有野心的设计简报，找到超越平庸 AI 垃圾内容的新想法。
  2. 定义（Define）：推动 AI 突破其惯用模式，并将多个模型串联起来，充分实现设计潜力，从而确立独特的设计个性。
  3. 交付（Deliver）：打磨掉粗糙草率的棱角，聚焦关键元素，交付惊艳的最终成果。

遵循这些阶段，并运用每个阶段中的技巧，你就能在极短的时间内做出出色的设计，让人忍不住问：“为什么 AI 能为你变出魔法（却不能为我）？”

探索：发掘可能性的空间

设计过程中最难的，是面对一块拥有无限可能的空白屏幕。应对这一刻的最佳方式，是先广泛探索，再深入打磨。AI 是探索各种潜在方向的绝佳工具。

不过，正如我们所知，模型往往过度依赖熟悉的模式，做出保守的选择。想要探索完整的设计空间，就得引导模型反其道而行：大胆、多样、敢于冒险。下面是两种把它推出舒适区的方法。

技巧 1：用种子字符串注入多样性

这里的思路是让模型找到新的设计灵感来源，而不是依赖它在训练中学到的默认套路。如果你试过用提示词让模型设计网站或应用，大概已经见过这种默认效果是什么样了。

举个简单的示例，我给四个 Claude Code 实例下达了同样的提示词：

提示词：

为我的效率应用做一个落地页。

Claude Opus 5：

几乎每次，我们得到的都是偏紫色的渐变、左边文字、右边图形，以及完全相同的结构。它看起来就像所有 AI 设计出来的网站。

我们并没有要求模型做任何独特或多样的设计，所以它一再退回到自己熟悉的模式也在情理之中。但仅仅要求多样性并不管用：

提示词：

为我的效率应用做一个落地页。给我完全独特的东西。每个设计决策都完全随机。

Claude Opus 5：

结果与之前有所不同，但依然缺乏多样性。模型始终使用相同的配色方案、相同的结构，甚至还有同样别扭的陶艺比喻。它预测出的 Token 只是听起来随机，而并非真正随机。

问题在于，模型天生无法真正随机地行动。它只能预测最有可能出现的 Token。如果想要多样性，就必须从模型之外引入。一种做法是 String Seed of Thought，由 Sakana AI 发表。我们让 AI 生成一串随机字符串，并把它当作设计灵感。这样，模型每次做出的决策才会真正不同。

提示词：

我想让你为我的效率应用做一个落地页。

请按以下步骤进行：

  1. 用 shell 脚本生成一串很长的随机字母数字字符串。
  2. 根据这串字符串确定创意方向（配色、布局、排版等）。不要只看表面，去寻找其中的子模式、特殊数字，以及任何能启发你的东西。
  3. 凭你的判断力把这个方向落地，让它看起来出色。

不要在设计中展示这串字符串，它只是用来给你提供灵感的。

Claude Opus 5：

输出一下子丰富多了！现在我们看到了不同的配色、字体和新想法。之前的设计，任何 Claude 用户都能得到；而这些设计独一无二，每次运行都不会得到相同的结果。

技巧 2：让你的提示词更有野心

给模型强力推动的另一种方法，是让提示词更具体、更大胆。这样模型就有了清晰的愿景作为决策依据，而不是临场随意发挥。找到独特创意的最佳方式，是把你自己的品味带进来。你先想象灵感来源——一款电子游戏、一种室内设计潮流、一件装置艺术——再描述你希望这种灵感如何影响 AI 的输出。以下是一些示例：

“为我的效率应用做一个落地页，采用大胆的像素艺术主题和惊艳的图形。每个板块都应该像游戏里的一帧画面，但整体上仍要能作为落地页正常运作。”

“为我的效率应用做一个落地页，设定在一座等距视角、充满生气的 3D 城市中，不同的功能以某种方式对应不同的街区或建筑。”

“为我的效率应用做一个落地页，采用极端不对称的布局、不和谐的配色与排版，以及令人不适的留白。打破所有规则，但依然要好看。”

当然，难点在于想出值得去要求的原创点子。AI 也能帮上忙，但如果你只是让它给你一些点子，得到的只会是人人都能得到的平均水平的答案。下面是我用 AI 寻找独特提示词灵感的一套方法：

1. 让 AI 列出一大堆点子，并且刻意不要太详细。目的只是激发你的想象力。

我想为我的产品设计一种大胆、独特的设计语言。你能尽可能多地列出点子吗？每个配上简短、概括性的描述。要广，不要深。

2. 把你喜欢的方向可视化，留意自己对不同方向的反应，然后让 AI 继续优化它们。

工业控制面板：

  • 我设想的是有触感的东西：按下去咔哒作响、很有满足感的按钮，配上好听的音效。
  • 一开始我想到的是卡通风或拟物风，但现在觉得有点俗气，请避开。
  • 我想要的是风格统一的组件，再加上一些小细节，在不过火的前提下体现这种质感。
  • 灰色渐变会显得很无聊，需要更多质感。也许可以在保留控制面板感觉的同时加入一些色彩？

你能根据我的品味把这个方向再打磨得更锐利一些吗？

3. 不断迭代直到满意，然后让 AI 写出用来构建它的提示词。

你能写一段简洁的提示词，让 AI 智能体据此构建一个初步的 POC 页面吗？

如果你只是把 AI 生成的点子原样再丢回给 AI，很难得到独特的东西。毕竟，任何人都可能做出同样的事。但当你主动引导设计方向时，最终得到的就是只有你才能创造出来的作品。

不要害怕尝试那些听起来很糟糕的点子。如果你发现自己在想“这绝对行不通”，那你多半走对了路。很多时候，你的智能体会给你惊喜，你会发现自己低估了它。如果没有，那就把结果扔掉，换个方向再试。但请保存那些没有奏效的提示词，等新模型发布后再测试一遍。这样，你就能确保自己充分利用了最新模型的能力。

定义：深化你的设计方向

到目前为止，我们已经了解了如何探索大量的点子，并有望得到一个有潜力的初始设计。然而，无论怎么写提示词，AI 生成的初始设计通常仍然会显得千篇一律。

我们的下一个目标，是通过不同的设计选择，让每个设计都有自己的个性。下面是我最喜欢的几种做法。

技巧 3：用子智能体建立正向反馈循环

我们需要不断迭代设计来改进它。但是，单纯让智能体看着设计然后改进它是行不通的，因为智能体并不客观：它审视的是自己的代码、过往的决策和之前的思路。AI 很难跳出来看全局，也很难“换个思路”。

要解决这个问题，不要让编码智能体自己决定设计何时足够好，而是让它去请教另一个智能体——一位“设计评审”。评审的工作是查看当前设计的截图并给出反馈。它不关心当前设计是怎么实现的，也不关心花了多少功夫，只关心设计是否真正达到了质量标准。

这种做法还有一个额外的好处：我们可以让评审使用大而昂贵的模型，又不会花费过高，因为只有在做关键决策时才会用到它。便宜又快的模型负责干体力活，强大的评审模型则负责提供品味。

让我们在之前的设计上试一试，用 Claude Fable 5 担任评审：

提示词：

我想让你改进这个设计。为了确定重点改进什么，请使用一个 Fable 5 子智能体作为设计评审。

每次迭代请遵循以下流程：

  • 截取当前设计的截图
  • 在全新的上下文中调用评审，只提供截图，不提供代码、实现细节，也不提供之前的迭代或评审意见
  • 让它评估该设计追求的美学风格，想象顶级设计工作室会如何呈现这种美学，然后指出最大的差距
  • 最后，让它给出一个满分 10 分的评分，表明当前设计距离工作室级别的质量标准有多近

请在评审的提示词中提供以下指引：

  • 它既要从高层思考整体结构与构图，也要审视细枝末节
  • 它要警惕那些过度使用、过于夸张或明显带有 AI 生成痕迹的模式，并为此扣分
  • 它应给出精准、具体的反馈，而不是含糊的长篇大论
  • 它要敢于表达鲜明的观点，而不是依赖安全、省事的做法

只有当评审者独立判定作品达到 9/10 或更高时，你的工作才算完成。不要把这条标准写进评审者的提示词，让它的打分保持客观。每次都使用同一份评审者提示词。

Claude Opus 5：

不再是千篇一律的同一套版式，每个设计现在都有了自己的个性，同时依然保留最初的整体美学风格。

值得注意的是，在每种情况下，Fable 产生的输出 Token 都不到 10%。如果直接让 Fable 重新设计页面，成本会翻倍，耗时也会长得多。

这些循环的搭建方式非常关键。以下是一些提示：

  • 确保评审者的评判标准尽可能清晰、客观。
  • 差：“判断我们的设计是否好看，而不是 AI 生成的。”这太主观了，每次运行的结果都会大相径庭。
  • 尚可：“审视我们想要的美学风格，想象顶级设计工作室会如何实现它，然后以此为标杆评判我们设计的质量。”这个提示词仍然含糊，但它提供了一致的框架和质量标杆。
  • 优秀：“这里有 5 个设计：4 个专业示例和 1 张我们产品的截图。请按精致度和品味高低排序。”这条指令具体而客观，并为判断提供了视觉基准。
  • 提供示例图片来展示目标质量标杆。你可以使用可比的截图、你喜欢的设计，甚至是 AI 生成的概念图。要指示评审者把这些当作基准或情绪板，而不是目标。你不希望它直接照搬其他设计。
  • 谨慎设定停止条件。否则评审者可能永远觉得设计不够好，而你的智能体会为了取悦它无谓地消耗 Token。先让它做一两轮迭代，观察是否在收敛，再决定是否增加轮数。
  • 为每项工作选择合适的模型。评审者角色可以考虑更大的模型，因为参数越多，通常设计感越好，想法的分布也越广。小模型可以胜任实现者，但也不能太小，你仍然需要一个能把设计方向执行到位的模型。

技巧 4：用图像生成丰富设计

编程智能体热衷写代码，却通常不会引入图片。它们往往选择更省事的代码方案：渐变、形状和基础图案。这些都是 AI 生成设计的明显特征。

有些智能体内置了图像工具，但用得不够充分。另一些没有现成的图像工具，不过可以很方便地通过 API 密钥调用 OpenAI 或 Gemini 的 API 来生成图像。

我们拿上一步的设计来试试：

提示词：

这个设计相当平淡。请用图像生成增添更多个性。可以考虑把 shader 或 3D 效果与图像结合，做出更有趣的视觉效果。

图像生成请使用这个 OpenAI API 密钥（仅在本地使用，不要存储在代码或产品中）：sk-a1b2c3d4…

请在浏览器中逐帧检查，确认你的成果看起来没问题。

Claude Opus 5（前后对比）：

这样的图像和效果可以迅速增添许多个性，让设计不那么明显地带有 AI 生成的痕迹，因为它们体现出的用心不止停留在表面。

根据你的环境，有几种不同的方式可以把智能体接入图像生成工具：

  • 如果你使用 Codex、Antigravity 或 Grok Build：
  • 告诉智能体使用其内置的图像生成功能。智能体本来就知道怎么做，只是不明确指示就很少使用。
  • 如果你使用 Claude Code 或其他智能体，同时拥有 ChatGPT 订阅：
  • 告诉智能体：“用 Codex CLI 生成图像。如果还没安装，请帮我安装。确保计费走我的订阅，而不是 API 密钥。”这样你就能用 ChatGPT 订阅生成图像，无需额外付费。
  • 如果你只使用 Claude 或其他单一工具：
  • 最简单的做法，是给你的智能体一个 OpenAI 或 Gemini 的 API 密钥，让它来生成图片。我建议专门为智能体创建一个单独的 API 密钥，并设置严格的消费上限。这样即使密钥泄露或被智能体滥用，成本也在可控范围内，而且你可以随时撤销该密钥，不影响其他工作。
  • 如果你经常要把密钥粘贴到对话里，不妨把它们放进一个文件，并在项目中让智能体去读取。你可以这样告诉它：“创建一个被 gitignore 忽略的文件 .env.agents，把这个 API 密钥存进去，并在 AGENTS.md/CLAUDE.md 中给自己留一条备注：这些密钥仅供你在开发期间使用（但不得随产品一起发布）。”

技巧 5：想要更高级的动效，就用视频生成

技巧 6：删掉没有价值的元素

AI 喜欢做加法，却很少做减法。设计一眼看上去像 AI 生成的最大特征之一，就是什么都解释一遍，或者包含没有实际用途的元素。相比之下，懂得克制的设计会立刻显得高级而有品位。
