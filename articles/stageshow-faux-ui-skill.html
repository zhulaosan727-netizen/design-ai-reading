01 三句话结论

第一，今天多数好模型已经能「做出」假界面，真正拉开差距的是那一百个小决定。营销页英雄区、功能卡片、bento 网格里的产品窗，看起来只是插图，却比真产品更难：它既要读起来像真的在被使用，又不能真的把整套产品塞进去。没有单独的 skill，结果往往又笨又满：每条列表都写满真实句子，整个应用被缩进一张卡片，光标瞬移，循环到最后一帧猛地跳回开头。

第二，Stageshow 的方法不是再写一串形容词，而是把作者反复验证过的决定写成可执行的流程。先选媒介和外观，再写三到五个节拍（beat），从最接近的金样例（gold example）改起，然后才画屏幕、编排运动、把整段演示拍成接触印样（contact sheet）逐帧看。技能里还有一套很小的 React 零件库（kit）：舞台、按真实几何画的窗口和手机、必须经得住逐帧检查的运动。它不提供「一种风格」，只把最容易塌掉的部分托住。

第三，品味听起来神秘，多半其实是做了又验证过的小决定，所以可以写下来。这和「品味只能看见之后才知道」并不打架：写得清的，变成规则、样例和检查；写不清的，仍然要人看一遍。作者自己也说，这是他的品味，不是一份中立标准。模型在进步，一部分早期规则已经失去作用；真正撑过每一代模型的，往往是取景和运动——模型其实做得到，只是没人告诉它这些事重要。

02 假界面为什么常常一眼假

Taylor 做了很多这种演示，体会是：单独看哪一步都不难，难的是同时做对一百件小事，而每一件都会被看见。智能体现在已经能交差，可交差和「像样」之间，隔的正是这些小事。

假界面有一个容易被忽略的任务定义。它不是产品截图，也不是线框。它要让人在一两秒内相信：这是一个正在被使用的真产品，同时只保留观众需要的那一层。信息太多，人会去读，插图就变成了微型应用；信息太少，它又缩回线框，不像产品。窗口要不要完整出现、光标要不要出场、循环的接缝放在哪里，全都决定它看起来是「做出来的演示」，还是「贴上去的截图」。

所以它比许多真界面更需要方向。真界面至少还有任务和数据把你拉住；假界面如果没有取景和故事，模型就会动用自己最熟悉的那套「一个完整的应用长什么样」——于是你得到一个缩小的、塞满了的、四平八稳的窗口。

编者点评：用 AI 做了一年网站的人，大概都在首页英雄区见过这个场面。你只是说「做一段产品演示」，回来的却是圆角大卡片里嵌着完整桌面应用：地址栏、侧栏、满屏表格，每个单元格都有真实句子。它技术上没错，观感上像把一张截图缩进了卡片。问题通常不在模型会不会画界面，而在你有没有先告诉它：观众这一秒该看什么，其他东西为什么只需要露出一截。

03 五种失败：过满、过空、被框住、发平、没味道

Taylor 把智能体常犯的错收成五种。本领越高的模型，越容易在「过满」上翻车，因为它知道一个收件箱里「应该」有什么，于是每一行都写满。

失败看起来像什么根子上缺了什么
过满（too much）每个单元格都是真实句子，排得又满又紧，人忍不住去读没区分「故事需要的词」和「只用来撑起体量的占位」
过空（too little）线框感太重，读不出来这是一个产品产品该有的铬件（chrome）、图标和材质被一起省掉了
被框住（boxed）整个窗口缩进一张卡片，像贴上去的截图没有先做裁切（crop）：窗口没有钉在边角、没有伸出画面
发平（flat）所有东西一样重，没有主次没有让「故事需要的那一张卡片」从环境里滑出来
没味道（bland）brief 里的风格完全没出现，谁的产品都长这样外观（look）没有被当成一等参数：主题、调色、用多少真词

这五种里，最值得单独钉住的是「被框住」。技能附带的演练场（playground）里有一组并排对照：同一件事做坏和做好。作者说，「不要把整个应用缩进卡片」谁都同意，也谁都会跳过；一旦并排放在眼前，就很难再假装没看见。

编者点评：这五种也可以当成评审用语，不必先装技能。打开一版英雄区，先问：我是在读界面，还是在看一个被取过景的故事？如果目光在第三行正文上停住，多半是过满；如果窗口四边都老实地缩在卡片里，多半是被框住。用语比「再精致一点」有用，因为它指向一个可改的决定，而不是一种气氛。

04 一句总纲，和它反对的默认动作

It reads as a real product, simplified to what the viewer needs, framed with intent, and every motion has a cause. — Benji Taylor / Stageshow

这是整份技能绕着转的一句话：读起来像真产品，简化到观众需要的程度，有意识地取景，每一个动作都有原因。四个分句其实是四道闸。像真产品，所以不能画成线框；简化，所以不能让人去读每一行；取景，所以不能把完整窗口居中塞进卡片；有原因，所以状态不能自己跳变——要有光标、手指或一条说得清的系统行为，把它连起来。

这句话也直接反对模型的默认动作。模型知道一个支持工单收件箱里有什么，就会把每一行填满。技能要求：只保留故事需要的那几个真实字符串，其余用占位线撑住「这里是满的」这个体量，却不要求你读。它还要求先决定裁切，免得在观众根本看不见的区域上花时间。

作者用同一段演示，拆成五个累积的状态，让人看见默认和取景之间的距离。故事很简单：有人把一条支持对话指派给 Maya。

状态画面上发生了什么还缺什么
1. 屏幕（Screen）整扇窗口，安静的灰色，真词只用在故事处正确，但像一张被框住的截图
2. 取景（Frame）窗口钉在边角并伸出画面，故事需要的那张卡片滑进来有主次了，但还没有时间
3. 剧本（Script）菜单打开，选中 Maya，再复位没有光标，一切像自己在动
4. 光标（Cursor）每个变化都有原因若最后 Maya 自己消失，循环的接缝仍会露馅
5. 循环（Loop）头像飞到一行并停住，光标再在画面里把操作撤销接缝看不见，演示才站得住

放任不管，智能体往第一种靠。它不是不会做后面四步，是没有把「取景和因果」当成必须先做的决定。

05 先决定取景，再决定画什么

取景是这篇里最能立刻用上的技术，也不只适用于动画。窗口通常是英雄，它的铬件是观众认出「这是什么」的第一线索。给原生 Mac 应用画上地址栏，整张图都会读成编的。技能里甚至没有一个单独的「种类」属性：你传入什么，铬件就跟过来；三颗窗口按钮在每一种窗口里都落在同一个位置。

手机也一样，而且运动逻辑不同：手机靠触摸，不靠光标。作者强调一种很容易偷懒、也很容易露馅的处理——把整部手机完整放进画面。更好的做法是让它伸出边框，永远不要整机出现。两台设备同场时更是如此：笔记本窗口里订一次会议，下一秒受邀人的手机伸出画面边缘，接住邀请。

bento 网格则常常以另一种方式被框住：每一块都给自己做一扇小窗，整组最后读起来像一堵截图墙。技能的改法是把网格当成一张图来规划：大约三分之一到一半的格子展示界面，窗口铬件只出现一次，相邻两块不要同一种类——一块是窗，一块是统计，一块是物件，一块是图解。

编者点评：可以把「取景」从营销页搬到 B 端产品的发布说明、空状态和功能介绍里。例如要解释「把工单指派给同事」，不要放一张完整后台截图，先决定观众该看见什么：搜索、结果、头像落进一行。窗口从左上角长出画面，右侧和底部被裁掉；列表里只有这两个名字是真的，其余是占位线。先裁切，再让模型去填像素，比事后再提示「请更有设计感」有效得多。

06 七步工作流：代码之前把决定做完

技能给智能体的，是一条大部分发生在写代码之前的工作流。这很重要：假界面翻车，通常不是 React 写错了，而是开写时还没决定这是静帧还是循环、观众看的是哪一块、故事有几拍。

步骤这一步要决定什么
1. 媒介（Medium）静帧还是动画，循环还是只播一次，它在页面上的位置和尺寸
2. 外观（Look）浅色、深色、蓝图（blueprint）还是玻璃；单强调色还是单色；产品真实的铬件和图标
3. 故事（Story）使用时的感觉、一条穿过应用的流程，或系统自己在做的事；然后写成三到五个节拍
4. 样例（Examples）找到最接近的金样例，改成 brief 里的产品：裁什么、什么和什么交叠、一条沟宽（gutter）
5. 屏幕（Screen）少数真实字符串，其余全部用占位线
6. 编排（Choreograph）哪些节拍重叠，哪一组错开（stagger），循环怎样精确回到起点
7. 彩排（Rehearse）拍下来，逐帧看，在手机宽度下检查，看循环接缝；再把它贴到最接近的金样例旁边

第四步是关键的转向。作者发现，只把规则写给智能体，往往走不远。你告诉它「让窗口伸出画面边缘」，它几乎不怎么伸；你给它一个已经伸出边缘的样例，它就能做对。所以技能里带着几十个金样例，从英雄区演示、bento 网格，到手机滑动、仪表盘配锁屏。工作方式不是从空白画布想象，而是先复制最接近的那一个，再改成你的产品。

07 舞台、脚本、光标、机位

每一段演示都是一个舞台（stage）：一块有设计尺寸的画布。内容由状态绘出，剧本一次改一个节拍。光标是舞台的一部分，按名字瞄准元素。零件在过渡期间保持挂载，才能滑进滑出而不是弹出；位置是测量出来的，所以光标能落在对的地方，叠加层在任何尺寸下都能对齐。

光标必须像手：按距离计时的浅弧线，按下的动作要能看见。整个站点只选一种光标样式，这样同一页上的每段演示都朝同一方向指，剧本也不必改。它还会在越过不同元素时变形——输入框上是 I 形，按钮上是手，画布上是十字——由元素自己声明，不必写进剧本。如果你把光标拿掉，变化仍会播放，但会像系统自己在演，缺少「有人做了这件事」的因果。

舞台上还可以架一台摄像机（camera），推近要紧的地方再拉回。它叠在场景之上，所以不必为了推近去改场景本身。作者举过一个很清楚的例子：四十天的运行时间里有一天坏了，镜头推到那一天，再拉回来。

外观是主题、调色，以及用多少真词。它们是舞台上的属性，靠替换 kit 的颜色工作：同一场戏写一次，浅色、深色、蓝图、极简（真词变成线条）都能跟着走。外观也可以来自你自己的设计系统——kit 的颜色、字体、圆角和间距都是令牌（token），智能体读取产品令牌再映射上去。这样演示用的是你的真颜色、真字体、真圆角，放在真产品旁边时，才不会像一份冒充它的模型稿。

编者点评：如果你已经在用设计令牌做站点，这一段比「再写细一点的视觉提示」更值得先做。把颜色、字体、圆角、间距做成智能体读得到的令牌表，再允许它把这张表映射到演示零件上。否则模型再有品味，也只是在用一套和你的产品无关的好看默认值。假界面一旦和真产品并排出现，最容易露馅的不是动效，而是差了两号的圆角和一种从没在产品里出现过的蓝。

08 为什么要拍成接触印样

智能体越来越会检查自己的工作，但常用的两种办法都看不见运动的中间过程：把代码再读一遍，或等画面落定后截一张图。假界面的毛病偏偏住在中间——一粒胶囊飞进来时跳了 4 像素，或者有一帧全部淡出。这两件事，定格截图和读代码都抓不到。

Stageshow 因此改成「拍电影」：把整段演示拍成一页接触印样，附一份能量化的报告，再让智能体去看播放本身——报告测不出的东西，仍要靠看。技能里还有专门抓「单帧跳动」的脚本，以及检查文字和控件是否溢出盒子的脚本。彩排这一步不是修饰，它是工作流的最后一闸。

编者点评：这条对做动效的人几乎可以直接搬到别的工具里。不要只看结束状态，把过渡导出为逐帧条，或者至少用 0.25 倍速看三遍循环接缝。特别要盯：元素是滑走的还是瞬移的，循环回到第一帧时有没有跳，数字滚动是不是只翻动了变化的那几位。能写成检查脚本的，就不要只靠「感觉不对再改一改」。

09 规则不够，要有金样例和对照

Taylor 测试技能的办法很硬：给一个全新的智能体这份技能和一句短提示，别的什么都不给；再用同一句提示去问一个没有技能的智能体，把两份结果并排放。只要看见不对的地方，他忍住自己下手改，把问题写下来，更新技能，然后从头再跑一轮。他这样做了很多次。

文章里给了六组对照，涵盖静帧图解、深色 bento、Mac 写作应用的循环英雄区、仪表盘上的一次尖峰、iPhone 消息、跨两块屏幕的会议预约。没有技能时，即使最好的模型也会过火：有时只差一个细节就显得粗糙，比如笨拙的光标，或一枚假的 iOS 状态栏；有时更糟，元素重叠或排齐。有技能时，结果更接近他会亲手做的样子。但他写得很清楚：技能是有立场的，里面很多只是他的品味。

Taste sounds mysterious, but most of it is small decisions made over and over until you know which ones hold up. That’s why it can be written down. — Benji Taylor / Stageshow

这句出现在文末的脚注里，却几乎是全文的方法论。品味不是气氛，是一批被反复验证、证明站得住的小决定。也正因为此，它不可能是中立的：写下的是作者的品味，不是「正确界面」的宇宙标准。

演练场把这件事变得可教。它收录技能里的全部样例、单独摆出的 kit 零件，以及好坏对照。样例同时给人和给智能体看。规则负责说出「不要怎样」，对照负责让「怎样才算对」无法被跳过。

11 可粘贴：brief 模板，以及把纠错写回 Skill

作者建议先从小的做起：一个交互，一个产品，一个尺寸。下面这份 brief 按他的七步写成可粘贴的模板。先填空，再交给已经安装 Stageshow（或你自己那份同等技能）的智能体；没有该技能时，也可以把模板当作清单，自己盯这七项有没有被决定。

请做一段假界面演示。先按下面七项做决定，写给我看，我确认后再写代码。

1. 媒介：静帧 / 循环动画 / 只播一次。放在页面的【英雄区 / 功能卡片 / bento 中的一块】，设计尺寸【宽 × 高】。
2. 外观：【浅色 / 深色 / 蓝图 / 玻璃】；【单强调色 / 单色】。铬件必须符合产品种类：【浏览器 / 原生 Mac 应用 / iPhone / 无铬件的卡片】，使用产品真实图标。不要发明产品里没有的地址栏、状态栏或窗口按钮。
3. 故事：【使用时的感觉 / 一条穿过应用的流程 / 系统自己在做的事】。写成 3–5 个节拍，每一拍都有可见的原因（光标、手指，或说得清的系统行为）。
4. 取景：不要把整个应用缩进卡片。窗口或手机钉在【哪一个边角】并伸出画面，不要整件出现。故事需要的那一个物件从环境里滑出来。若是网格：只有部分格子展示界面，窗口铬件只出现一次，相邻块不要同类。
5. 屏幕：真实字符串只准出现这些：【列出】。其余全部用占位线，保持「是满的」这个体量，但不要求阅读。
6. 运动：光标按距离走浅弧线，按下要能看见；零件滑进滑出，不要弹出。循环必须在画面里把操作撤销，结束位置与开始完全重合，接缝不可见。
7. 彩排：把整段拍成接触印样（或逐帧条），检查中间帧跳动、文字溢出、循环接缝，并在手机宽度下看一遍。再把它和最接近的金样例并排放，列出三处仍不如样例的地方并改掉。

一句话 brief：【例如：首页英雄区，有人把一条任务指派给同事。】
产品令牌（如有）：【颜色 / 字体 / 圆角 / 间距的文件或链接】。

作者还留了一条很能积累的工作习惯。技能里的大多数规则，最初只是写在某一版演示边上的一句笔记，例如「阴影太重」或「这个标题没有居中」。笔记一旦进了技能，后面每一版都免费获得它。你也可以这样做：纠正一版演示之后，让智能体把这条笔记加进技能，而不是只改这一次画面。

刚才这条纠正不要只改画面。把它写成一条带原因的短规则，追加进我们的假界面技能：
- 看见了什么问题
- 以后遇到同类情况应该怎么做
- 为什么（一句）
不要写形容词，写可检查的决定。

12 自查清单

  • 这段假界面要讲的故事，我能写成三到五个有原因的节拍吗？还是只有「展示一下产品」？
  • 窗口或手机是钉在边角并伸出画面，还是完整地缩进一张卡片里，像贴上去的截图？
  • 真词是不是只出现在故事需要的地方？其余是否用占位线撑住了体量，却不引诱人去读？
  • 铬件是否跟产品种类一致？有没有给原生应用加上地址栏，或画了一枚经不起核对的系统状态栏？
  • 若是网格：窗口铬件是否只出现一次？相邻块是不是不同类？是不是每一块都在重复同一扇小窗？
  • 每一个状态变化，是否都能指出它的原因——光标、手指，或一条说得清的系统行为？
  • 光标是按距离走浅弧线，还是在两点之间瞬移？按下看得见吗？整站是否只用一种光标样式？
  • 循环是否在画面里把操作撤销，结束点与开始完全重合？我有没有用 0.25 倍速看过接缝？
  • 我检查的是运动的中间过程（接触印样 / 逐帧 / 慢放），还是只看了落定后的截图和代码？
  • 演示用的颜色、字体、圆角、间距，是产品令牌映射来的，还是另一套「好看的默认值」？
  • 这一版是从最接近的金样例改来的，还是从空白重新想象的？并排放过吗？
  • 我刚才做的那条纠正，有没有写回技能，让下一版免费获得它？

14 它的边界，以及它为何愿意让自己过时

检查能抓住错误，抓不住无聊。一段演示可以通过每一项量化检查，仍然不值得看。技能不会替你判断「这个故事有没有看头」，那一眼还是得自己看。

它也不会画画。需要插画或摄影的部分，更好的做法是人手做好再放进去，而不是指望技能凭空生成。

作者对这份技能的寿命也写得很坦然：模型的品味在一代一代变好，他怀疑这类技能只在一段时间内有用——它教的和附带的许多东西，很快就会变成模型自带的能力。有一部分已经发生了。制作早期，参考文档里还有「把窗口按钮保持在正确大小」这类规则；模型变好之后，这些规则悄悄不再起作用。另一些则在他试过的每一代模型上都还站得住，尤其是取景和运动。模型其实有能力做对这两件事，只是在有人提醒之前，它们似乎并不知道这两件事重要。

在那之前，它仍然有用。用它做出来的每一段演示，本身也是这类界面的一个做工认真的例子，而这正是模型会从中学习的东西。如果它因此在某一天不再被需要，作者并不觉得可惜。

若只记住一件事：假界面不是把应用缩小后贴进卡片。先决定观众该看什么，先裁切，再让每一个变化都有原因；看的时候不要只看结束状态，要把中间过程拍下来。模型会做界面，但通常要等你告诉它，取景和因果是重要的。
