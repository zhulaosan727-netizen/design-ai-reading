从草图、线框图到原型，这套旧的设计阶梯之所以存在，是因为做出真东西成本太高。如今编程智能体几分钟就能把它做出来，创意工作的重心也就变成了探索与取舍。本文整理了与智能体协作处理视觉类工作的实用方法：用图片代替形容词，要求多个版本，对抗智能体向平均水准靠拢的惯性，并把每个想法都变成可以亲手操控的 playground。

保真度阶梯已经消失

设计一直在攀登一条保真度的阶梯。先在纸上画草图，再做线框图，然后是视觉稿，接着是可点击的原型，直到最后才有人真正动手构建成品。每一级台阶存在的理由都一样：成品的成本很高，所以要趁改主意还很便宜的时候，尽可能多地敲定问题。

现在，编程智能体能在几分钟内，用真实的媒介、真实的动效、数据和交互，把成品做出来。它同样快地做出第二版、第十版，而且不会厌倦。

过去直接跳到成品是鲁莽之举，现在却是验证想法是否可行的最便宜方式。

草图无法告诉你一段动画手感如何，布局在每种宽度下表现怎样，也无法告诉你一种质感看起来是纸张还是噪点。而成品可以。

新的前沿是纯粹的创造力

你不再受限于执行能力。精细复杂的动画、每次访问都不同的生成式背景、会响应光标的交互作品：这些过去需要专家、数周工作量和相应预算的东西，如今在浏览器里一个下午就能完成。

只要你能想象出来，就能做出来。

人人都在发布平均水准

环顾四周。现在人人都能做网站或应用，而几乎每个新作品看起来都一样：同样的模板、同样的渐变、同样的组件库、同样的首屏，下面摆着同样的三张卡片。它们看着还行，却很无聊，甚至往往不够精致，因为默认设置已经“好到可以发布”。让构建变容易的工具，也让平均水准变得容易，而大多数人发布的正是平均水准。

当人人都能做出像样的网站或应用，“像样”就不再出众。

这正是机会所在。如今想要脱颖而出，就要超越它：去做那些你一直想做、却苦于没有时间或技能去实现的惊艳、愉悦、出人意料的作品。过去耗在执行上的精力，现在可以投入到雄心上。

简而言之

所以，执行不再是你的瓶颈，你的想象力和品味才是。你现在是艺术总监：智能体负责产出，你来决定什么最好看、什么有意思、什么契合你的品牌、什么能让用户眼前一亮。这些不是非对即错的判断，而是选择，要通过观察、比较和不断突破来做出，而把它们做好、并且志存高远，就是你的工作。这需要一种不同的工作方式。以下这些做法能带来真正的差别，来自一位设计师在多次长时间会话中与编码智能体协作处理视觉工作的经验。它们都不需要特殊工具：一个图像模型、一个编码智能体和一个浏览器就够了。

  • 多展示，少描述。用 ChatGPT 或其他图像模型生成参考图，再交给智能体。一张图承载着数百个决策，形容词几乎什么也承载不了。
  • 要十个版本，而不是一个。并排展示，并提供开关在它们之间切换。挑出你的最爱，说出每个版本中你喜欢的点，然后在此基础上迭代。选择比描述更容易。
  • 对抗平均化。智能体容易滑向千篇一律，并死守已经做好的东西。要明确要求多样性、广度，以及与上一个毫无关系的方向。
  • 点名技术。Canvas、WebGL 和 shader 能实现纯 HTML 与 CSS 做不到的效果。你不必亲自写，但必须提出要求。
  • 搭建一个 playground。让智能体把每个参数都变成控件，并给出很宽的取值范围。它可能会变得很复杂，这没关系。
  • 不要索要修改，而要索要控制权。如果你不喜欢某处，就让它给你一个滑块，自己去找到想要的效果。
  • 保存一切。快照、命名版本、持久化的设置。正是它们让大胆的实验变得安全。

在真实成品中探索

第一个转变发生在你的头脑中。当一个可运行的高保真版本只需几分钟，你就不必一步步从草图推进：从一开始就在最终的媒介中探索，合理的尝试次数会提高一个数量级。过去一个视觉想法只能在流程末尾得到一个精心制作的原型，现在第一天就能得到二十个可运行的版本。

这是一份礼物，但前提是你用它来探索，而不是更快地打磨你的第一个想法。扔掉的要比留下的多。有意思的方向很少是第一个，也很少是显而易见的那个，而智能体会很乐意先把显而易见的那个做出来。

硬币的另一面是：当一切成本都很低时，人很容易一直尝试却什么也没学到。每一轮之后，都要说清楚它为什么不行（“太杂乱”“让人联想到一栋建筑”“和文字抢戏”）。这些理由会累积成一份比最初锐利得多的需求说明，而这恰恰是智能体无法替你提供的部分。

给智能体看图，而不是堆形容词

“微妙”“有机”“更高级”“不太对味”：这些词对你来说意思精确，对模型来说却很模糊。不过，编码智能体可以读图，而一张图同时承载着成百上千个决定：比例、密度、色彩、质感，以及留白的多少。

所以，去做图：

  • 生成参考图。让 ChatGPT 或其他图像模型根据你的构想生成粗略的效果图，哪怕里面错误百出。把它们连同一条备注交给智能体：“方向对了，但线条应该更细”。
  • 指向具体的效果或概念。不是一堆你喜欢的东西拼成的情绪板，而是你想从参考中拿到的那一个点：你多年前做的流图（streamgraph）里色带分叉的方式、某幅印刷品上的颗粒感、某个菜单的缓动曲线。把它展示出来，并点明关键的部分（“我要的是这种分叉，不是这些颜色”）。你自己过去的作品往往是最好的参考，因为你清楚地知道其中哪一部分是对的。
  • 直接指出问题所在。一张当前版本的截图，加一个箭头和一句话（“这部分总是向右弯”），胜过一大段描述。

每当你从文字切换到图片，都可以期待下一个版本有飞跃式的提升。

一次要十个版本

不要只向智能体要“一个首屏动画”。要十个，并带一个可以在它们之间切换的控件。比较远比描述容易：十个并排放在一起，会告诉你自己喜欢什么、什么让你意外，以及哪些是你永远想不到要去提的。

然后挑出你最喜欢的两三个，别只选一个，并说明每个喜欢在哪里（“3 的动效，7 的配色”）。接着围绕这些版本要求下一轮：十个新版本，把你喜欢的方向推得更远，并融合各自的优点。再挑一次，继续往下走。几轮下来，你会到达任何单个提示词都无法到达的地方，就像育种能培育出任何单株植物都无法长成的品种。

另外，不时让它再出十个与之前任何一个都毫无关系的版本，免得过早收窄方向。

对抗向平均值的牵引

语言模型给出的是最可能的答案，而在视觉工作中，最可能的答案就是平均值：均匀的间距、到处套用的同一种质感、所有元素一样的宽度、一成不变的节奏。真实的材质、纸张、笔触、光线、人群，从来都不是平均的。

智能体也倾向于守着已经做出来的东西。你要“不一样的”，得到的往往只是当前版本的变体，而不是一个新想法。

这正是你最重要的地方。智能体不会自己离开中间路线，但你指向哪里，它就能去哪里。所以要明确指向：说出你想尝试的具体方向，而不是笼统的“不一样”。“如果这些不是线条，而是纸条呢？”“试试做成印刷品的效果，带套印偏差。”“让它像鸟群一样运动，而不是像波浪。”这些方向，智能体自己永远不会选，但它几分钟就能做出来。你的品味、你的参考，以及你多年来一直揣着的那些奇思妙想，恰恰是它所缺少的。

然后，明确而反复地对抗向平均值的牵引：

  • 点名要求变化。“宽度要有很大差异，宽的窄的混着来，不要统一。”这话你可能得说不止一次。
  • 要求跨度。“让这三个版本彼此之间尽可能不同。”
  • 让它推倒重来。“忘掉当前的做法。给我三个完全不用它的方向。”
  • 说明你想要多大的改动。智能体往往会对你的最新一条消息反应过度，把你喜欢的部分也重做一遍。“细微调整，其他保持不变”，每次都值得说一遍。

知道该要求哪种技术

Canvas、3D 和 shader 过去属于专家领域：那是另一类编程，有自己的一套数学，大多数设计师和前端开发者从未碰过。这个时代结束了。智能体写这类代码就像写布局一样轻松，所以它们不再令人生畏，只是多了几个选项。

Canvas、3D 和 shader 不再可怕，它们只是多出来的选项。

你不必亲自写代码，但知道有哪些可能性，会改变你得到的结果。放任不管的话，智能体会选择最保险的方案：HTML 元素加 CSS 动画。做一个按钮没问题，但要做有野心的东西，这就会把你牢牢限制住。

点出具体的技术，全新的选择就会打开：

  • Canvas：同时绘制成千上万个运动的对象，比如粒子、线束、生成式图案，以及任何多到页面元素承载不了的东西。
  • WebGL：在 GPU 上实时渲染图形，包括景深、光照、大型场景和全屏流畅的动效。three.js 这类库让它变得实用。
  • Shader：让作品显得精心打磨而非机器生成的利器，比如颗粒感、纸张与印刷质感、模糊、辉光、扭曲，以及像墨水一样交融的色彩。Shader 在 GPU 上对每个像素运行，所以原本不可能实现的效果也能流畅呈现。
  • SVG：清晰、可缩放的插画与图形，适合需要精确控制的动画。
  • 噪声与物理模拟：让运动显得自然而非机械，比如流动、漂移、群聚、沉降。

你不必了解它们的原理，只需知道它们擅长什么。这样当智能体第一次尝试碰壁时，你就可以说“用 fragment shader 来实现”或“在 canvas 上绘制”。拿不准时，也可以让它解释各种选项：“这个效果有哪三种实现方式，各自能带来什么可能？”

把每个想法都变成一个 playground

这是最能改变工作节奏的模式。不要向智能体要答案，而是向它要一件工具：

把每个参数都做成控件。为每个参数给出一个设定值和一个浮动范围，并且让范围足够宽，能给我带来惊喜。

智能体会把控件直接构建进作品本身：一个可拖动的小面板，里面有滑块、开关和取色器，悬浮在真实的页面或应用之上，一次点击就能隐藏。这样每次调整都能在原位、在上下文中、以完整尺寸看到效果。从此你探索的速度是拖动滑块的速度，而不是聊天一来一回的速度。原本要来回折腾一个晚上的事，一分钟就能搞定。

它可以做得很复杂，这没问题。一个动画的 playground 可以扩展到几十甚至上百个控件，分成可折叠的分组，还带搜索。智能体做这类工具又快又好，而且这个面板反正也不会随产品发布。

几个很值得做的细节：

  • 设定值加变化幅度（variance），而不只是一个数值。这样你得到的是可控的多样性，而不是千篇一律。
  • 宽范围。智能体设定的范围往往很保守，又是同样被安全的中间地带吸引：每个滑块都在有趣的地方之前戛然而止。要让它给出远超“看起来合理”的范围，向两个方向都推到极端。如果滑块还是不够远，那就再要一个更大的范围；你随时可以收回来，但滑块够不到的地方，你就无从探索。
  • 按钮式随机。加一个“shuffle”（随机）控件，有时还可以决定在最终版本中保留随机性，让每次呈现都略有不同。

别要求改动，要求控件

有了 playground 之后，就要改变给反馈的方式。当某处不合心意时，不要让智能体去改它（“把线条再细一点”），而是让它加一个能改它的控件（“加一个控制线条粗细的控件，并带上变化幅度”）。

然后自己去调。你会比用语言描述更快找到想要的效果，也会明白这个参数究竟有多重要，而且当你下次改主意时，这个控件还在那里。

这样智能体也更容易把你的需求做对。“让它更优雅一些”只是在猜；“这个滑块需要调得更远”或“我需要一个控制颜色混合程度的控件”才是精确的指令。

保存快照并持久化设置

好的状态很脆弱。下一次实验，或者智能体的下一次过度反应，都可能抹掉你喜欢的版本，而你也记不住确切的设置。

让 playground 具备记忆：

  • 持久化设置，刷新后依然保留，不会丢失当前进度。
  • 以文本形式复制和粘贴状态。把喜欢的状态连同“lock this one in”一起粘贴到对话中，让智能体保存下来。
  • 命名快照：在 playground 中保存，方便在最佳候选之间来回切换。
  • 勤提交（commit），并在开始清理之前，为 playground 保留一个备份分支。

重点不在于整洁。一旦你喜欢的东西不会丢失，你就会更愿意尝试大胆的想法。

让设计简报保持鲜活

长会话容易跑偏。经过几十轮修改后，智能体可能已经悄悄丢掉了你一开始提出的某些要求。当结果开始走样时，让它把到目前为止的所有指令汇总成一份完整的需求说明，再据此重新构建。重新梳理一遍需求，往往比任何一次单独的纠正都更有效。

此外，也要时不时从细节中抽身出来。最大的改进往往来自消除问题，而不是解决问题：直接展示真实图片，而不是用代码模仿它们的风格；或者干脆砍掉一个功能，而不是反复调优。这种退一步的判断，智能体不会主动去做。

像工程师一样收尾

外观确定之后，就该切换模式了。让智能体把选定的参数固化到正式版本中，删掉所有没用到的东西，并做好性能优化：在没人会注意的地方降低分辨率，动效稳定后降低帧率，在低端设备上也能平稳运行。这正是智能体最擅长的部分。

请保留这个 playground。下次有人说“跟这个一样，但稍微不同一点”时，你会用得上。

去做你一直想做的东西

只要你能指明方向，智能体就能把任何东西做出来，但它不会凭空想出什么新点子。放任不管，它做出来的就是平均水平，而平均水平正是其他人都在发布的东西。点子、冷门的参考、没人会尝试的方向，以及做出真正令人愉悦之作的雄心，都必须来自你。

这正是机会所在。过去，执行力是横在想象与实现之间的一堵墙，对大多数人来说，它决定了什么能被做出来。如今这堵墙已经消失。所以，别再用智能体更快地做出另一个还不错、却让人记不住的网站或应用。用它去做那个惊艳、出人意料、你一直想做却苦于没时间或没技能的东西。
