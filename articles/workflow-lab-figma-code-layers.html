01 三句话结论

第一，code layers 解决的是「可交互原型被锁在单人工具里」。分头在 vibe-coding 工具里试想法，很难并排比细节，也难接住队友刚做好的交互；把代码原型（code-backed prototype）贴回画布，比较、评论、分叉才回到多人设计的默认姿势。

第二，一次提示可以要三条方向，并排放在画布上点着试。原文 Pickup 市集 App 的例子：在地图页加「配送地址」入口，第一条指定全搜索地址栏（omnisearch），另外两条让 Agent 惊喜——地图选点、快捷地址（已存地址 / 当前位置）。队友能直接操作，再评论或 fork。

第三，探索不是终点：合并层 + 画布上的 Spec（规格说明），才接到工程。选中两份探索层让 Agent 合并；再让它写 Markdown Spec，标出相对原版改了什么、哪些牵涉后端 / API，留给开发者审阅。原型与决策史都留在画布上。

概念一句话对 Zhu 的用处

02 问题：分工具探索为什么贵

痛点不是「不会 vibe coding」，而是探索被拆成孤岛：每个人在各自工具里生成可点原型，文件散落、交互细节对不齐，更难在别人成果上继续改。设计评审变成「看录屏」或「轮流投屏」，失去画布上并排标注的带宽。

对个人站 / 读本这类小产品同样成立：你用 AI 搭站点约一年，很多交互想法（卡片 hover、双语对照、筛选）会在 Cursor / 外部 Agent 里试完，再截图贴回 Figma——谱系断了，下一次战役还要从零描述上下文。

编者点评：贵的不是生成一次原型，而是「比较税」与「交接税」。code layers 的价值主张，是把比较和交接重新放回多人已经熟悉的画布，而不是再发明一个协作产品。

03 七种把代码放到画布上的方式

原文列出多条创建路径，可按「手里已有什么」选入口：

  1. Chrome 扩展捕获网页 → 粘贴到画布成 code layer
  2. 选中设计 frame → 提示 Figma agent 转成可交互 code layer
  3. 空 code layer → 从零提示 Agent 生成
  4. 克隆已连接的 GitHub 仓库到画布
  5. 上传代码文件夹
  6. 外部编码 Agent 经 MCP 导入
  7. 从描述 / PRD 起空层（可用 Notion connector 共享 PRD）

Pickup 故事走的是第 4 条：设计师把 GitHub 仓库克隆为画布上的 code layer（地图视图），再在其上开分支式探索。对 Zhu：若读本或 azuredesign.cn 已有仓库，克隆上画布比「口头描述现有信息架构」便宜得多；若还在纯设计阶段，用第 2 条从 frame 起步更自然。

04 一次提示要三条方向：并排交互原型

关键纪律：不要一次只要一个「最好的」。原文提示大意是——做三个变体，在地图页加配送按钮；点击后可选地址；第一条用 omnisearch 地址栏，另外两条让我惊喜。

Agent 在画布上并排出三个可点版本：

  • Option 1：地址搜索（omnisearch）
  • Option 2：地图选点
  • Option 3：地址快捷方式（已存地址 / 当前位置）

队友当场试、在画布评论，也可对某一层再 fork。这比「三个独立沙盒链接 + 口头对齐」更接近设计评审的肌肉记忆。

和 No.49 Weave 的对照：Weave 用 Branch 并排创意物料路径；code layers 用并排可交互代码层并排产品交互路径。都是「探索不覆盖原版」，媒介不同。

05 双轨编辑：代码编辑器 ↔ Extract designs

细化时先 Option/Alt 拖拽复制层，保留原版再改。打开代码编辑器：左侧 Agent 对话、中间预览、Files 看代码。也可走手动路径：Edit → 选中标题 → 在属性里改字号 → Apply，只更新该层代码。

另一侧是 Extract designs：把当前屏幕、特定元素，或 Record flow（录制流程）抽成可编辑的 Figma 设计层。例子：给 “Delivery options” 标签加留白；按钮文案改成 “Choose delivery address”。再 Update code layer，把设计侧改动写回可运行原型。

纪律很清晰：交互逻辑与状态机优先在代码层试；视觉节奏、文案、间距在设计层精修；最后写回，避免「设计稿很美、原型还是旧的」。

06 合并队友探索 + Spec 给工程

故事后半：队友在地图聚类上探索（地图数字标记 vs 附近商品网格），并留下评论。设计师选中「网格聚类」那层 + 「配送」探索层，提示 Agent：新建一层，合并网格聚类与配送能力。得到一份可跑的合并体验。

然后让 Agent 在画布写 Spec（Markdown）：相对原版改了什么、哪些点牵涉后端 / API，方便开发者审查。通向生产的路径是：可工作原型 + 技术 Spec 留在画布 → 开发者标出仍需实现 / 测试的部分 → 代码可回分支或开 PR；探索、评论与 Spec 留作决策史。原文注明 code layers 已对全部用户开放公测（open beta）。

07 对照表：分工具 vibe coding vs code layers

分工具 vibe coding画布上的 code layers
比较细节多窗口 / 录屏，难对齐像素与文案并排图层，同屏点、同屏评
接力队友导出链接或重述上下文直接 fork 层，上下文在画布
设计精修常在设计工具重画一截Extract designs → 改完 Update code layer
给工程原型 + 口头 / 另写文档原型 + 画布 Spec，决策史可回看
与仓库关系易成一次性沙盒可从 GitHub 克隆，也可回 PR
适合个人快速验证单一想法多人比较、合并、交接

若你仍是一个人周末实验个人站，分工具未必错；一旦需要「和自己上周的版本并排比」或「让工程看清 API 缺口」，画布层更省解释成本。

08 可粘贴提示词模板

# A. 三方向探索（改成你的页面与约束）
Make three variations of this and add [新入口] to the [页面].
When clicked, the user can [完成的任务].
The first one should be [明确方案], but surprise me with the other two.
Keep existing [品牌色 / 组件库 / 路由] unchanged unless required.

# B. 合并两层
Create a new code layer combining [能力 A] from [层名 A]
and [能力 B] from [层名 B].
Preserve working interactions from both; resolve conflicts in favor of [优先级].

# C. 画布 Spec（给工程）
Write a Spec (Markdown) on the canvas documenting changes vs the original.
Flag backend/API implications and anything that still needs building or testing.
List open questions for developer review.

模板用法：A 解决「探索带宽」；B 解决「把评论里夸过的两段拼回去」；C 解决「可点 ≠ 可交付」。三步缺一会重新掉回分工具的交接黑洞。

09 和读本相关篇怎么排

  1. No.26 判断留给你：Agent 做杂活，人留判断——本篇的「手改属性 / Extract 后再写回」是同一纪律的代码原型版。
  2. No.28 Figma Make 反向交接：设计师改代码推 PR；本篇补上「推 PR 之前，多人如何在画布上并排试与合并」。
  3. No.35 设计与代码 Agent 同步：两边上下文对齐；code layers 让同步发生在同一画布对象上。
  4. No.15 Agent 上画布：Agent 直接在 Figma 设计；本篇把「可运行代码」也变成画布一等公民。
  5. No.38 Specs Markdown：Markdown 当协作容器；本篇让 Spec 紧挨着被合并的 code layer，服务工程审阅。
  6. No.43 Codex + Figma MCP：外部编码 Agent 经 MCP 进出画布——正是创建 code layer 的第 6 条路径。
  7. 本篇：把可交互代码原型变成可并排、可合并、可写 Spec 的画布工作流。

10 自查清单

  • 我是在并排比较可点原型，还是在收集互不相关的沙盒链接？
  • 一次探索有没有故意要 ≥2 条方向，避免过早收敛？
  • 细化前有没有复制层，避免毁掉可回退的原版？
  • 视觉与文案小改，是走了 Extract designs，还是整段重新生成？
  • 合并前，两层各自被队友点过并留下评论了吗？
  • 交给工程的是否包含画布 Spec（含 API / 后端风险），而不只是「能点」？
  • 仓库来源清晰吗——克隆自哪条分支、探索是否准备回 PR？
  • 这条决策史（层、评论、Spec）下周还能在同一文件里找到吗？

一句话收束：code layers 把 vibe coding 的爽感，接回设计画布的多人肌肉。并排试的是交互，不是截图；合并的是可运行层，不是口头折中；留给工程的是原型加 Spec，不是「你看录屏吧」。探索可以热闹，交付必须可回放。
